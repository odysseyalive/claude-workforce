# Claude Workforce install manifest
#
# The single authoritative list of every file the installers ship.
# Consumed by BOTH installers: `install` (bash, Linux/macOS) and
# `install.ps1` (PowerShell, Windows). Add every new shipped file here;
# there are no per-installer fetch loops to keep in sync.
#
# Format: [flag] <path relative to repo root>
#   (no flag)  fetch unconditionally, overwriting any existing copy
#   keep       fetch only if absent on the host (user-editable file; never clobber)
#   hook       fetch unconditionally; chmod +x. Registered to a harness event by
#              `/workforce hooks --execute`; `verify` reports whether it is wired
#   exec       fetch unconditionally; chmod +x. Invoked by a procedure for its
#              exit code; registered to nothing
#   style      fetch unconditionally into <config-root>/output-styles/ (personal) or
#              .claude/output-styles/ (project) — NOT the skill directory. An output
#              style is only found there. Selected by `outputStyle` in a settings
#              file, which `/workforce hooks --execute` writes
#   canary     fetch unconditionally into <config-root>/agents/ (personal) or
#              .claude/agents/ (project) — NOT the skill directory. A measurement
#              fixture, not an employee: it must be REGISTERED as an agent before
#              `staging.md` Phase C or D can spawn it, and it is shipped so the first
#              audit finds it already there rather than having to write it
#
#   retired    NOT fetched, and not a shipped file. A path this project USED to
#              install OUTSIDE the skill directory and no longer ships. It exists so
#              the prune can reach a host whose `.installed-external` record predates
#              the record itself — see § Retired external paths at the foot of this file
#
# THIS LIST IS THE FLAG SET, and it is complete. Both installers branch on all six
# and every reader that strips a flag must strip all five. `canary` went undocumented
# here from the day it was added until 2026-09-07 while five rows used it, and
# release-verifier's own completeness check — which its handbook orders to read the
# set "off manifest.txt's own header, never from memory" — would have derived four
# flags and mis-stripped every canary row, reporting five present files as ABSENT.
# That is the same false-ABSENT failure `style` caused two days earlier, reproduced
# by the instruction written to prevent it. Found by the cold reader probing
# release-verifier.
#
# NOTE on `hook` vs `exec`. Mechanically identical — both chmod +x — and two words
# because the DISTINCTION IS THE THING BEING TRACKED, not the file mode. A `hook`
# fires unprompted and needs a wiring command and a wired/orphaned report; an
# `exec` is called by name and its absence is loud on the next invocation.
# references/enforcement.md § Nothing ships dormant draws the line.
#
# `keep` has no users: no shipped file is user-editable, because project state
# lives in the project (references/scopes.md). It is retained because the grammar
# is shared with claude-enforcer's installers; not a dead branch to "clean up"
# without checking that shared grammar first.
#
# HISTORY, because this line moved twice on 2026-08-03 and the second move
# corrected the first. The four inherited hooks were deleted for good reasons and
# the deletion was then generalized into "ships no executables" — which forbade
# the scripts too, so `audit` Step 1b hand-derived a census and `verify`
# re-specified in prose what a script asserts, in the project whose second
# directive is to automate everywhere feasible. Narrowing that to "ships no hooks"
# was the same over-reach one level down: the finding underneath was never about
# file type, it was that A MECHANISM SHIPPING UNWIRED ENFORCES NOTHING AND LOOKS
# LIKE IT DOES. So hooks ship, with the wiring command whose absence was the
# actual defect.
#
# Host destination: .claude/skills/workforce/<path minus leading "workforce/">

# org-config.template.md is the SHIPPED TEMPLATE for the per-project config
# (tier -> model/effort, department roster, per-project markers).
#
# It is fetched UNCONDITIONALLY and is never edited by the user. `/workforce audit`
# instantiates it once into ${CLAUDE_PROJECT_DIR}/.claude/workforce/org-config.md
# and never clobbers that copy afterwards.
#
# Why a template rather than claude-enforcer's `keep`-flagged in-skill file: the
# skill may be installed at USER scope (~/.claude/skills/workforce/), where a single
# in-skill config would be shared by every project on the machine — department
# rosters and tier->model tables silently colliding across unrelated orgs. `keep`
# protects a file from re-download; it cannot protect it from being in the wrong
# scope. Project state lives in the project. See references/scopes.md.

# ── The five evaluator skills — SIBLINGS, not files inside workforce ─────────────
#
# THE USER DIRECTIVE OF 2026-09-10 (SKILL.md § Directives): *"the five evaluations and
# workforce should be self-contained in the user during install so that I don't have to run
# an audit every time there are changes. All I have to do is update workforce."* These rows
# are the whole of that mechanism. `sibling` installs to `<skills-root>/<name>/…` — beside
# `skills/workforce/`, not inside it — because a skill is discoverable at
# `<skills-root>/<name>/SKILL.md` and nowhere else.
#
# WHAT CAME BEFORE, AND WHY IT DID NOT REACH ANYBODY. v1.48.0 moved the catalog CORPUS into
# the install under `references/catalogs/<kind>/` and left the five SKILLS per-project.
# MEASURED 2026-09-10: `~/.claude/skills` held `workforce` alone while
# `odyssey-alive/.claude/skills` held all five. `update` ran, verified 368/368 files, and
# reached none of them — three of five kinds then resolved from the project copy and the
# shipped corpus reached no reader in that project. A corpus that advances under a skill
# that does not is not a propagation path.
#
# THE CORPUS MOVED WITH THE SKILL rather than being duplicated beside it. Each skill's
# `references/` IS the shipped catalog — one copy per install, advanced by `update`, read by
# the skill that owns it and by `wf-catalog` for any employee that greps it. Shipping the
# same corpus twice in one install would be two canonical texts, which is the failure the
# catalogs were consolidated to end.
#
# A SIBLING NEVER OVERWRITES A SKILL THIS INSTALLER DID NOT WRITE. `install` decides
# ownership per skill, once, on its `SKILL.md`, against `.installed-external`. Measured
# reason: `odyssey-alive/.claude/skills/text-eval/SKILL.md` carries an
# `origin: user | immutable: true` block of the user's own directives.
# PROVENANCE, three kinds, because one prefix now holds all three and the contracts differ.
# VENDORED, NOT AUTHORED: `text-eval/references/text-tells.md` and the `code-evaluator`
# corpus are byte-identical imports from claude-enforcer. Keep their own anchors, never
# edit here — rewriting one forks a corpus that has one origin; update by re-copying.
# AUTHORED HERE, NOT VENDORED: each `additions.md` is workforce's own slot and the
# only sanctioned place to GROW a catalog; each `SKILL.md`; and the whole `security-evaluator`
# corpus, distilled and cited from OWASP/PayloadsAllTheThings/semgrep rather than copied.
# `bin/check` keys its VENDORED exemption on exactly these names, so a file filed wrong
# either escapes the authoring rules or is frozen by a read-only contract it never had.

# ── Retired external paths ───────────────────────────────────────────────────
#
# WHAT THIS IS FOR, and it is one specific hole. `prune_scope` rule 2 refuses to
# delete anything in `agents/` or `output-styles/` unless a previous run of the
# installer recorded writing it, by exact path, in `.installed-external`. That rule
# is right — a basename match would delete a user's own agent that happened to share
# a name — but the record was ADDED with the prune, on 2026-09-09. Every install
# made before that date has no record, so on those hosts rule 2 has nothing to read
# and the prune's first run skips the external files entirely.
#
# MEASURED on this maintainer's own machine, 2026-09-09: `.installed-external` absent
# at `~/.claude/skills/workforce/`, five `wf-canary-*.md` in `~/.claude/agents/` and
# `plain-speak.md` in `~/.claude/output-styles/` — all six shipped by a release that
# no longer ships them, all six invisible to the prune that exists to remove them.
# Five of them appear in the agent menu of every session on the machine.
#
# So the record is SEEDED from this list when it is absent. That keeps rule 2's
# safety property exactly: these are paths this project shipped, named explicitly,
# never inferred from a basename or a directory scan. A user's own agent cannot
# appear here, because the list is authored from this repository's own history.
#
# Destination is derived from the source directory, the same mapping the live flags
# use: `workforce/canary/*` -> the agents directory, `workforce/output-styles/*` ->
# the output-styles directory. A retired path outside those two prefixes is a
# manifest error and `bin/check` fails on it rather than guessing.
#
# A row is added here when a `canary` or `style` row is removed, in the same commit.
# Rows are never deleted: a host can be arbitrarily old, and a list that forgets an
# entry re-opens exactly the hole it was written to close.
