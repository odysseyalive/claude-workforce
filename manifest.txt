# Claude Workforce install manifest
#
# The single authoritative list of every file the installers ship.
# Consumed by BOTH installers: `install` (bash, Linux/macOS) and
# `install.ps1` (PowerShell, Windows). Add every new shipped file here;
# there are no per-installer fetch loops to keep in sync.
#
# Format: [flag] <path relative to repo root>
#   (no flag)  fetch unconditionally, overwriting any existing copy
#   keep       fetch only if absent on the host (user-editable file; never clobber)
#   hook       fetch unconditionally; chmod +x. Registered to a harness event by
#              `/workforce hooks --execute`; `verify` reports whether it is wired
#   exec       fetch unconditionally; chmod +x. Invoked by a procedure for its
#              exit code; registered to nothing
#
# NOTE on `hook` vs `exec`. Mechanically identical — both chmod +x — and two words
# because the DISTINCTION IS THE THING BEING TRACKED, not the file mode. A `hook`
# fires unprompted and needs a wiring command and a wired/orphaned report; an
# `exec` is called by name and its absence is loud on the next invocation.
# references/enforcement.md § Nothing ships dormant draws the line.
#
# `keep` has no users: no shipped file is user-editable, because project state
# lives in the project (references/scopes.md). It is retained because the grammar
# is shared with claude-enforcer's installers; not a dead branch to "clean up"
# without checking that shared grammar first.
#
# HISTORY, because this line moved twice on 2026-08-03 and the second move
# corrected the first. The four inherited hooks were deleted for good reasons and
# the deletion was then generalized into "ships no executables" — which forbade
# the scripts too, so `audit` Step 1b hand-derived a census and `verify`
# re-specified in prose what a script asserts, in the project whose second
# directive is to automate everywhere feasible. Narrowing that to "ships no hooks"
# was the same over-reach one level down: the finding underneath was never about
# file type, it was that A MECHANISM SHIPPING UNWIRED ENFORCES NOTHING AND LOOKS
# LIKE IT DOES. So hooks ship, with the wiring command whose absence was the
# actual defect.
#
# Host destination: .claude/skills/workforce/<path minus leading "workforce/">

# org-config.template.md is the SHIPPED TEMPLATE for the per-project config
# (tier -> model/effort, department roster, per-project markers).
#
# It is fetched UNCONDITIONALLY and is never edited by the user. `/workforce audit`
# instantiates it once into ${CLAUDE_PROJECT_DIR}/.claude/workforce/org-config.md
# and never clobbers that copy afterwards.
#
# Why a template rather than claude-enforcer's `keep`-flagged in-skill file: the
# skill may be installed at USER scope (~/.claude/skills/workforce/), where a single
# in-skill config would be shared by every project on the machine — department
# rosters and tier->model tables silently colliding across unrelated orgs. `keep`
# protects a file from re-download; it cannot protect it from being in the wrong
# scope. Project state lives in the project. See references/scopes.md.
workforce/references/org-config.template.md
