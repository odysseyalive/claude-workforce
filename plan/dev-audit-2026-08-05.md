# `/workforce dev audit` against claude-workforce — 2026-08-05

Asked to run it. It did not complete, and both reasons are findings rather than failures.

## Blocker 0 — the mode was declared and unimplemented

**`dev` appeared in exactly two places**: `SKILL.md` (the command table and the Self-Exclusion Rule)
and `intent-router.md` (never synthesize it). **`audit.md` mentioned neither `dev` nor
self-exclusion.** So the documented way to point this tool at its own repository had **no defined
behaviour**, and running it meant inventing a procedure step — which Core Principle 5 forbids.

The consumer-named/producer-assumed shape, in the escape hatch of the command that exists to find it.

**Fixed before running**, and the scope is derived from the reason for the rule rather than widened
past it. Self-exclusion exists because *"converting the dispatcher into an agent creates a dispatch
loop"*, and typing `dev` does not stop that being true:

| | |
|---|---|
| `dev` **includes** `workforce` and `org` | in the census, survey, dispositions, conform pass, and every printed count |
| `dev` **never converts** them | RETAIN, reason cited — a refusal of an ACT, and the run continues |
| `dev` never hires from, retires, reduces, or sweeps them | T7b/T7c skip them, and the summary says so per skill |

Two assertions, each proven by breaking it.

Nothing reconciles the two.

## Blocker 2 — the repository's own test corpus is surveyed as project content

This is the substantive one, and only running it surfaces it.

```
markers     15 families · 141 markers · 2 unpaired (sweep hazards)
immutable   41 sacred blocks in 31 files · 1 unterminated (extraction hazard)
```

Measured against the tree:

| | |
|---|---|
| both unpaired markers | `fixtures/f9-half-migrated/…/scarred/SKILL.md` and `fixtures/scripts/census-inverted/…/s/SKILL.md` — **corpora built to be malformed so the census can detect malformation** |
| files with sacred blocks | **21 in `fixtures/`, 21 outside it** — exactly half the "user directives" in this repo are test data |

So an unmodified `dev audit` would extract 21 files of fixture text as though they were the user's own
words, report two deliberately-broken fixtures as sweep hazards, and count a test corpus into the org
design. **`wf-census` has no concept of a test corpus** — there is no exclusion mechanism at all.

**How far this generalizes, stated honestly:** it is acute here because this project's fixtures *are*
`.claude/` trees. A repository whose fixtures are ordinary code would not hit it nearly as hard. But
the class is real for any tree that vendors or fixtures a `.claude/` directory, and the census offers
nothing for it.

## What was and was not done

**Done:** the `dev` specification, with assertions proven by breaking. The census run, read-only.

**Not done: no audit writes were made.** The run halts at the Atomic-or-Absent preconditions, which is
the gate working — and beyond the collisions, auditing this tree without a fixture-exclusion rule would
produce a survey built substantially from test data. Building that exclusion is a real feature with a
real design (what counts as a corpus, who declares it, how a false exclusion is detected), and it is
not something to improvise inside a run.

**765 assertions · 124/124 proven by breaking · 65 script fixtures · 6/6 idempotent.**

*The point stands from the other direction: this repository has shipped a tool for days that it could
not run against itself, and nobody knew, because nobody ran it.*
