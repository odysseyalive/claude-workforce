A chart is not just its roster, and the roster is not the first Employee table

BLOCKING DEFECT, measured by the operator with --dry-run over the six real
charts on this workstation: 33 adoptions proposed, ZERO of them new. Every one
was already charted. Two causes, and my own report called one of the false
rows "1 real adoption", which it was not.

1. THE ROSTER WAS FOUND BY THE FIRST TABLE HEADED `| Employee |`.
`apps-odyssey-alive` has four of them, and the first — at line 59 — is the
tier-ceiling evidence table, `| Employee | `disallowedTools: Agent` | `tools:`
allowlist omitting `Agent` |`. Its real roster is at line 167 under
`## Roster`, where `connector`, `copy-lead` and twenty-one others already sit.
So that project read as a roster of two evidence rows, 23 charted agents looked
new, and any row written would have been appended to the wrong table. The
anchor is now the table under the `## Roster` heading, and the Employee-header
search is only the fallback for a chart with no such heading — which
`playwright-mcp` genuinely is, keeping its roster under `## Structure`.

2. "ALREADY CHARTED" MEANT "IN THE ROSTER". A chart records an agent wherever
its author chose to. `hither-lands` keeps its 8 adopted agents in a separate
`## Adopted specialists` table with several backticked names to a cell —
`| `premortem-analyst`, `regression-hunter`, `skeptic` | … |`. `odyssey-alive`
names `frontend-design-inspiration-researcher` three times, in
`## Orchestrators` and in prose, and never in its roster, because the agent is
a symlink into the skill that owns it. The test is now a whole-token search
over everything the author wrote — word boundary on `[0-9A-Za-z_-]`, so
backticks, commas, pipes and brackets all count — and an agent found nowhere is
the only kind adopted. It reads neither the generated block nor the `Synced:`
line, or it would place every skill in itself and keep an agent charted after
its row was deleted by hand.

It errs toward "already charted": a short name can collide with a word in
prose. That is the right direction. A missed adoption costs one `/workforce org
index`; a wrong row is written into somebody else's chart by a hook they never
typed.

GHOST is unchanged in rule and now reads the right table: a roster row whose
name has no file, slug-shaped, with the operator-row exemption.

RE-MEASURED over all six real charts after the fix — claude-workforce,

Prove the two hang-and-name assertions on a counted pin, not a bare presence test

`bin/prove "org sync"` returned 6 of 8 PROVEN with 0 VACUOUS and 2 BAD-CASE —
findings about the two new CASES, not about the assertions. Both assertions
guard a property whose behaviour a deletion cannot break:

* `os.walk` already DEFAULTS to no link following, so removing the explicit
  keyword leaves the cycle fixed. What the keyword buys is that nobody tidies
  it to `True`.
* removing the name gate outright charts the unwritable name, which fails the
  fixture rows too, so the named assertion is never reached.

And a bare `in` test cannot be proven here at all. Breaking it means deleting
the literal, after which `every bin/prove case names a file that ships and a
literal that is in it` fires as well — which is BAD-CASE, not PROVEN. A
single-occurrence literal is therefore unprovable by construction, and that is
worth writing down once rather than rediscovering per case.

So each literal is written in the code AND in the paragraph recording the
measurement behind it, and `bin/check` counts the mentions: 2 for
`followlinks=False`, 3 for `NAME_RX`. Deleting the first mention fails the
count, leaves the file valid, changes no behaviour, and leaves the literal
present for the dead-case check to find. The behavioural halves are unchanged
and still do the real work: the timed run inside the cycle assertion, and the
`orgsync-hostile-name` fixture for the gate.

Verified on the mutation each case makes, before re-running the suite: pin
2 -> 1 and 3 -> 2, both fail the count, both files still parse, and both
literals survive for the dead-case check. `bin/check` 1453 passed / 0 failed,
`bin/script-conformance` 403/403, `bin/idempotence` org-sync ok.

A symlink cycle in .claude/agents hung the sync, and a declared name could end its own note

Two defects in aa5291f, both measured.

1. THE WALK FOLLOWED SYMLINKED DIRECTORIES. `glob.glob('**/*.md',
recursive=True)` descends into one, so `.claude/agents/d/up -> ..` beside
`d/self -> .` never terminates. Measured on exactly that tree: the glob exited
124 under `timeout 25`, while `os.walk(followlinks=False)` returned in 0.000s.
This hook fires at every session start and on every `Bash` call, so one cloned
repo carrying those two links stalled every session in it — and a hang has no
output, so it is the state hardest to diagnose. A symlinked .md FILE is still
read, which is how odyssey-alive registers an agent that lives inside a skill;
only a symlinked DIRECTORY is no longer descended into.

2. A DECLARED `name:` WENT INTO A NOTE RAW, and a note goes into the `Synced:`
HTML comment and into the hook's own `additionalContext`. A name carrying `-->`
closes the comment it is written into, a `|` splits the roster row, and an
arbitrary-length one floods the context of every tool call that follows. On a
clone that text is whoever wrote the tree.

`NAME_RX` decides what may be charted at all, and a name that cannot be written
as itself is REPORTED, never charted and never escaped — escaping the cell is
the worse answer, because the escaped row stops matching the name read back off
disk and the agent is adopted again on every pass, forever. Every name reaching
a note then goes through `safe_label` (the cell defang, bounded at 60), and
`summarize` bounds the notes list at ten with `and N more`.

Also here, and found by adding the loop fixture rather than reported: every
case in `bin/script-conformance` ran with NO timeout, so one fixture tree that
made a script loop would have taken the whole suite with it and printed
nothing. `CASE_TIMEOUT = 120` — generous next to the slowest real case, under a
second — and an expiry fails that case by name.

Gates: two fixtures carrying the exact layouts (`orgsync-symlink-loop`,
`orgsync-hostile-name`), two `bin/check` assertions — the cycle one RUNS the
hook with `timeout=25` and asserts under 20s, because a hang cannot be asserted
on its output — and two `bin/prove` cases. The cycle case proves the explicit
`followlinks=False` pin rather than the behaviour, and says why: `os.walk`
already defaults to False, so deleting the keyword cannot reintroduce the
cycle. What the keyword buys is that nobody tidies it to `True`.

Keep an org chart current on the events that add an agent, without an index

`org index` is a procedure a model follows by hand, and nothing else writes
`.claude/workforce/org-chart.md`. So every agent file that lands in
`.claude/agents/` — written this session, copied in, arriving on a `git pull`,
written by another session — is invisible to the roster `/org` dispatches from
until somebody types the command. Rung 8 notices at dispatch time and then asks
the user to run one.

*User request 2026-10-08: "when new skills, agents, etc are added into any
project, automatically the existing project org index needs updated".*

`wf-org-sync` writes only what can be derived without judgment: an ADOPTED
roster row for an agent the chart does not list (`org.md` step 1a), `GHOST` on
a charted row whose file is gone (step 4), and one marker-delimited `## Skills`
list rewritten whole from disk. It is NOT an index — no tier, no department, no
manager, no fan-out, no stamp — and it never touches `Generated:`, so that line
still says when a full index last ran. A separate `Synced:` line records the
hook's own pass, written ONLY beside a real change, which is what makes a run
with nothing to do write nothing and print nothing.

Wired on `PostToolUse` (`Edit|Write|MultiEdit|NotebookEdit|Bash` — a `cp` or a
`git pull` adds an agent exactly as a `Write` does) and on `SessionStart`, so
all three paths carry it through the one `--wire-defaults` producer: the
installer wires it, `audit` re-wires it, `verify` reports it absent, and an
already-installed machine picks it up on the next `update`.

MEASURED against the three real charts on this workstation, read-only. They do
not agree on shape: one heads its roster `| Employee | Tier | Dept | Reports to
| Model | Effort | Lane | Owns | Status |`, one uses `Model / Effort`, and one
has no `## Roster` heading at all — its roster is an `| Employee | … | Check |`
table under `## Structure` with no `Status` column. So the anchor is the header
cell `Employee` and every column is filled by its own name; a column that
cannot be filled mechanically is `—`. Result on those three: 0 rows ghosted,
1 real adoption found. Two of them carry a roster row for the person running
the session, and ghosting that would have reported the operator as a dead
employee on every run — so a row is ghosted only when its name is a plain agent
slug, is not a name a chart uses for the human, and `.claude/agents/` exists
and is not empty.

Two refusals stand in front of the write, because this hook fires unasked in
any tree somebody opens, a clone included. The target must resolve INSIDE the
project root, and the file must read as a chart. The provenance test is the
honesty line `org-chart-format.md` declares mandatory and verbatim rather than
the `AUTO-GENERATED by /workforce org index` comment — measured, two of the
three charts carry that comment and the third does not, so pinning it would
have refused a third of the charts the tool exists for. Write-through for a
symlinked chart is kept (gate rule 3); what is refused is a target the project
does not contain, and the resolved path is what gets written, so re-pointing
the link afterwards cannot redirect it.

A skill's `description:` and its directory name are not this project's text. On
a clone they are whoever wrote the tree, and a description carrying `-->` closes
the generated block's own HTML comment while one carrying the END marker's bytes
ends the block early — after which the next pass reads the markers as
unbalanced, calls it tampering, and the sync is dead. Both are defanged, pipes
escaped, backtick runs collapsed, 200 characters.

Gates: 14 `orgsync-*` fixture cases (new agent, new skill, GHOST with the
operator row untouched, no chart, settled, unbalanced markers, symlink
write-through, symlink out of the root, a file that is not a chart, no Status
column, hook payload, empty `--root`, hostile description), 5 `bin/check`
assertions with 6 `bin/prove` cases, and a `bin/idempotence` writer row on the
un-synced fixture — a settled tree would be a no-op twice over and measure
nothing.
