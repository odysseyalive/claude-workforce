A rule with no producer is a description (v1.29.0)

Three rules in this distribution were written, checked for their own presence, and
performed by nothing. Each is now built, wired, and proven by breaking it.

CORE-SKILL FORCE-REFRESH — audit.md Step 4 said "force-refresh the Core skills to
current shipped source, every run — never skipped, never offered, never a question"
and had no script, no counted line, and no check that anything ran. The evaluator
half of the same idea has all three. MEASURED across three audits of this
repository: .claude/skills/org carried 11 dispatch rungs against the shipped 15 —
rungs 12-15 never reached the dispatcher of the project that authored them — and
personnel-ledger lists 4 record types against 10.

  - workforce/bin/wf-companion is the producer. It replaces a MACHINE-OWNED REGION
    and nothing else: a Core skill with no such region is reported UNMANAGED and
    left alone, because audit-setup.md Step 0.3 state 3 holds that the shipped copy
    is the newcomer and the customization is the requirement. Measured here:
    operating-principles carries 18 items against 13 shipped, five of them this
    project's own, which a force-refresh that "won" would have deleted.
  - Its first run found the trap: org.md documents its own markers in prose one
    paragraph above the real block, so a bare find() matched that line for both,
    returned a span containing zero rungs, and would have written it over a
    project's dispatcher. The span search is line-anchored, with its own case.
  - Wired three ways: audit Step 4 calls it, verify grew a Core companion freshness
    section so drift is visible between audits, invariants row 38 (INV-CORE).

SYMLINK CENSUS — Atomic-or-Absent rule 3 ended "record both before the first write
and re-read them after, and a drop is the whole detector", and nothing recorded
anything: wf-census reported the counts and no caller compared them across a write.
wf-stamp now takes the census before its first write and re-reads it after, printing
INV-SYMLINK and failing the run on a loss or a RETARGET — resolved targets, not a
count, because a link that still exists pointing elsewhere reads clean as a number.
Invariants row 37. Measured while building it: Python's open(path,"w") FOLLOWS a
symlink and truncates the target, so it was never the hazard; the rename-in-place
family is, even when the pattern matches nothing.

bin/check HAD NO TRIGGER — 1,254 assertions ran only when a human typed the command.
No .github/, and githooks/pre-commit called only pre-commit-version, whose own
docstring named bin/check "the backstop at verify/CI time" — a time that never
arrived. It is now a pre-commit gate, failing closed, with WF_SKIP_CHECK=1 as the
documented bypass.

Drift fixed, each with a guard rather than a correction:
  - enforcement.md cited audit Step 6-G for the settings heal; that is Step 6-H.
  - Two mutable "ceiling of four" echoes now cite the section instead of restating a
    numeral the canonical table contradicts at six. The copy inside the immutable
    block is untouched.
  - conversion-taxonomy.md said "there are exactly three and none to spare" of tiers,
    which platform.md forbids; CONST_RX only matched "three tiers"/"three-tier", so
    the class was defined by meaning and matched by spelling. Widened, scoped to
    tiers by proximity, and bare "exactly three" deliberately left unmatched —
    deferred.md, audit.md and invariants.md each count three non-tier things, and a
    check that fires on those gets turned off.
  - A prove case paired "only an OPEN call can be the caller" with a deletion from
    expectations.json, but that check only read wf-handoff's text, so the case proved
    nothing. Its failure message cites handoff-self-collision as its evidence; the
    check now reads it. A check whose named evidence can vanish without it noticing
    is asserting from memory.
  - The Core-skill check pinned a hand-typed SPECIMEN of its report block. It passed
    for weeks while the refresh had no script. It now names the producer.
