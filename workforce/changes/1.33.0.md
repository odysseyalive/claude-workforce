A hook that reports what the turn read, and the nine commands that never existed

Two jobs in one release: finish the cleanup that had been half-applied since
morning, and ship the one mechanism three panel reviews agreed on.

THE PHANTOM COMMANDS ARE GONE. The skill's `description:` — the line Claude Code
reads to decide when to load workforce — advertised 33 commands and NINE had no
procedure file: ablate, budget, charter, diagnose, evals, promote, reconcile,
transfer, vendor. § Grounding says "read the procedure file for the invoked
command", so each routed a reader to a path that was not there. Seven appeared in
zero live files. The guard that should have caught it derived KNOWN_COMMANDS from
the description line itself and compared it against references to that line — one
half of a fact checked against itself, green while every advertised command was
unrunnable. It now also asserts an implementation exists.

`vendor` goes with them, on the user's call and for a better reason than mine. I
argued to keep it because "it is the only documented path for a remote repo" —
a claim about the DOCS that I never checked against the world. The installer is a
public one-liner; a clone can run it. Vendor's own doc admitted the cost: a
second, lower-precedence copy that never wins on your machine, whose only purpose
was staying in sync with the copy that does. Project-scope INSTALL stays — it
fetches the current release and `update --project` advances it, so there is no
snapshot to drift. The offline path is documented instead:
`WORKFORCE_REPO_URL="file:///path" ./install --user`.

`wf-turn-ledger` — A COUNT, NOT A CHECK. MEASURED across one working session: ten
times the operator settled on a wrong reading and defended it. NINE of the ten
escapes came from outside — six from the user, three from a spawned panel. The
tenth came from re-reading raw tool output. ZERO came from noticing. That retires
the whole family of self-checks: each needs the operator to DECIDE to run it, and
that decision is made by the impaired faculty. So this notices nothing. It tallies
the reads a turn made and prints them where the reader who demonstrably does
escape can see them.

It prints DISTINCT SOURCES, not raw reads. `3 reads · 1 distinct` is the shape of
this session's own failure: one document read three times, counted as
corroboration. ProvenanceGuard measures source accuracy falling to 0.229 with
semantically close sources — two files in one repo are close.

AND IT SHIPPED WITH THE BUG IT WAS BUILT TO PREVENT. The first version classified
Bash by substring; `grep -rn foo . 2>/dev/null` scored as a WRITE because `>` was
on the list, as did `python3 bin/check 2>&1 | grep passed`. It under-counted
exactly the reads it exists to surface. That is the substring failure that retired
wf-speak-guard at a measured 7.0%, one layer down — judging commands rather than
prose. There is no classifier now. A count has no false-positive rate; a
classifier does, and the header claimed the former while doing the latter.

THREE HOOK COUNTS, ALL WRONG. enforcement.md said "six hooks in its default set
and one opt-in" naming five scripts that no longer ship; two hundred lines later
the same file said "exactly one"; hooks.md tabled three. In the two files whose
job is refusing claims the runtime will not back. No file states the number now —
bin/check DERIVES it from SHIPPED_HOOKS and requires every wired hook to be in the
manifest, on disk, and described in the authority table. The old assertion keyed
on a prose phrase and broke on the rewrite rather than on the rule; its
replacement tests the property.

1.31.0` and asserted "nothing between" — true only while 1.31.0 was current, and
seven bumps in one afternoon broke it. Five fixture cases for the ledger,
