An ask the session answered is finished, and an earlier turn's item can still be marked

Measured in odyssey-alive's session 37f162e1: every Stop printed `ISSUES 6 open
issue(s) judged` with a KICKBACK row for each of i2-i7 and the list only grew,
while several of them were plainly handled.

Two causes, both closed here. `item_done` read six words, all of them meaning the
work shipped, so a question the session ANSWERED was never done and an ask the user
withdrew had no word to reach; `DONE_STATUSES` is now the set a session actually
writes, with anything unrecognised still open. And an item could only be updated
during the turn that wrote it, because the per-turn checklist is replaced on every
message and absorbs onto its own issue alone -- so the turn now CARRIES every
still-open item of this session's earlier issues, capped at 20 newest-first, each
tagged with its issue id, and the status it comes back with is written onto that
issue by `wf-widen`'s Stop and again by the next message. The write-back never
appends, reorders, or reaches a closed or unknown issue.

Six fixtures, each failing against HEAD first: answered closes, the withdrawn
family closes, a carried item marked done closes its earlier issue, a planted
carried row never edits another issue's item list, the cap holds newest-first, and
odyssey-alive's own ledger heals in one message with no migration step.

An id the hook cannot name is never said out loud, on the Stop as on the deny

421a89c validated the `PreToolUse` deny's agent ids because
`permissionDecisionReason` is model context. The main `Stop` says the same ids to
the same session through `systemMessage` and `reason`, and it was never validated:
a planted `agent_id` in the issue ledger was read out verbatim in the kickback.
Measured by the fixture before the fix — `missing 'RESUME the agent on this issue
with SendMessage'; present but forbidden: 'IGNORE THE ABOVE'`.

FOUR SINKS, NOT ONE. The action line, the escalation, `QUOTE_FRAME`'s `agent_id`,
and `judge_issue`'s two status lines all quoted whatever the file held.

THE VALIDATION NOW LIVES WITH THE NAMING, in `wf-task-tag`: `name_agents` for a
list of ids and `name_labelled` for the `id (type)` status form, both applying
`bare_name`. `resume_action` takes the LIST rather than finished text, so no
caller can hand the formatter an id nobody validated — the drift that opened this
hole in the first place. An unnameable id is DROPPED, not escaped, because
`bare_name` is an allowlist; with nothing nameable left the sentence still says
resume and simply names no one.

`wf-widen` filters `cut` at the source, which makes the other three sinks safe by
construction and removes a latent `KeyError` on an entry with a state and no id.
`wf-turn-budget` keeps its own `bare` filter: there it is control flow — an
unnameable held agent allows the spawn rather than denying it in terms the model
cannot act on — and the deny now names every held agent, matching the Stop.

bin/check pins the two reader calls at their new form, the validator inside the
naming, and wf-widen's source filter. bin/prove adds three cases; all seven
mutations on this check were verified to fire exactly one assertion and leave
every file parseable.

A cut agent is resumed, never replaced: the fresh spawn is refused where it is taken

MEASURED, trial e2e3 (session `bb8a3e53`, 2026-10-13). A cap-10 filer was cut and, in
the SAME main turn, the session spawned a second filer with the `Agent` tool and then a
third. Both cut agents stayed `handoff` in the ledger for the rest of the session and
neither was ever resumed. K8's RESUME kickback lives on the main `Stop`, and that
session never stopped between the three dispatches, so the one line that would have
corrected it had no event to fire on until all three runs were over.

THE GUARD. `wf-turn-budget` is registered a second time, on `PreToolUse` / `Agent`, and
denies a spawn whose `subagent_type` this session has a live `handoff` agent of. The
reason names the agent_id and the `SendMessage` resume. Main thread only (`agent_id`
absent), one role only, and four ways it lifts by itself: the issue closing, the resumed
agent's own next tool call, the mark ageing out, and a spawn of any other role. A
project with no issue ledger is never guarded.

THE STALE ESCAPE. `agent_handoff` now stamps `handoff_at`; `held_by` refuses to report a
mark older than 30 minutes or one with no stamp at all — every mark written by an
earlier release. A deny that cannot expire is a wedged session, which is worse than the
spawn it refuses.

THE RESUME FLIP WAS FIRING ON THE AGENT'S OWN NEXT CALL. The final notice lands at
`cap - 3`, which leaves three turns in the same allowance, and `last_claim` was bounded
at the CURRENT round — so the next tool call answered the cut that round had just
claimed and put the entry back to `running`. Filer `a26b1c41eecfb3119` was flipped that
way twice in e2e3; the harness then cut it for real and `agent_returned` recorded
`returned` on an agent that was holding work. The bound is now the round BEFORE this
one, which is the only thing a new allowance can be the resume of.

THE LANGUAGE. WARN and FINAL now ask the agent to say RESUME ME in the reply itself,
which is the only part of a cut run the manager reads.

Fixtures, each failing against 961d532 first: spawn-guard-cut-agent-of-the-same-role-is-
denied, -another-role-is-allowed, -no-cut-agent-is-allowed, -stale-mark-is-allowed,
turn-budget-same-allowance-call-is-not-a-resume, widen-handoff-two-cut-agents-are-both-
resumed. `${NOW}` joins `${TREE}` in script-conformance's `subst`, because "this mark is
live" is a fact about the clock and a checked-in epoch is stale the day after.
