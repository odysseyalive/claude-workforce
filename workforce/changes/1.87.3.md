wf-bash-stdin finds a shell's output file only under this user's own temp tree

The early-warning note searched every `claude-*` directory under shared
/tmp for a shell's output file, so another user's planted file could be
named in the stop line. It now walks only `<root>/claude-<uid>`, refuses
a link at every level (lstat, S_ISDIR/S_ISREG), requires each level to be
owned by this uid, and otherwise gives the TaskStop form only. wf-widen
was not affected: it uses the path the host wrote into the tool result.

Found by the automated commit security review of 1.87.2.
