The jury sits on results, and messages from other sessions are vetted like any ask

A request for work now carries a `work` kind closed by touch (jury-only,
never a channel block), read from the asker's words, never the reply.
A turn opened by a hand-back or task notification inherits the docket of
the ask that launched the work (agent ledger, or a shell's launching turn
via its tool-use-id, at most 4 hops, no newest-issue fallback). A tagged
turn always seats its jurors; a message delivered mid-turn joins the
running turn's docket. Jurors read the row that opened the turn, the
opening hand-back rides the flag as testimony, and a claim with no run
behind it is a verified no for touch. A command PreToolUse hook puts the
open issue's user words in front of Artifact and AskUserQuestion calls.
A background agent silent past 20 minutes is named once at the next Stop.

agent-say messages ([agent-msg from=...]) and teammate messages are read
through the same peer path as cross-session messages: an issue, a work
list and a docket from their own body, with no user authority.

Measured on 1,315 mutze-studio Stops: 33.5 more seated juries per 100
Stops at about 6.2 s each. bin/replay-seating replays the seating
decision on any transcript, report only.

Installs and updates edit settings files surgically instead of reformatting them

wf-settings-apply --wire-defaults reloaded settings.json and rewrote it
with dump(), so every --user install or update reformatted the user's
whole file. A new _write_settings turns the wanted change into character
edits, refuses unless the result parses to the wanted dict, and writes
nothing when nothing changed (bytes, mtime and inode kept). Applies at
user and project scope; a duplicate key is now refused, not silently
dropped. A differential over all 69 wf-settings-apply cases parses equal
to the previous output.

Your own advisor moves off a superseded model too, and laika's lineup reads

The superseded-model heal now also moves a user-scope advisorModel in
<config root>/settings.json, once per config root, at session start
(wf-heal) and on every --user install or update (wf-settings-apply
--wire-defaults). Only the value's characters change, a marker under
the config root records the move, and a hand re-pick stays.

parse_lineup finds a lineup table by its Model/Effort/Tier header row
instead of by section heading, so an org that records its lanes under
"## The lanes" no longer reads as (none selected). The other eight live
org-configs read byte-identically before and after.

Projects that chose a superseded model move to its successor, once

A new Superseded models table in Model statics maps claude-fable-5-1 to
claude-fable-5-2. A project that recorded the old ID in org-config.md,
an agent's model: line, or a project advisorModel moves to the new one

each move prints a MODEL MOVED line. A marker records the move, so a
hand re-pick of the old model stays. wf-model-lanes --check reports a
pending superseded value as drift and a hand re-pick as kept.
