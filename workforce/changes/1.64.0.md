Make wf-companion and wf-ledger writes atomic, byte-exact and contained

Fixes the five reviewed findings in the 1.63.0 fix batch:

1. A failed write truncated the constitution or the hand-kept index and
   never restored it. Every write now goes through wf-ledger.atomic_write:
   temp file in the target's directory, fsync, rename. A symlink inside the
   project is written through and survives; a hard-linked file is refused.
2. The migration read with universal newlines and errors="replace", so CRLF
   spans came back LF and Latin-1 became U+FFFD while the row said
   byte-identical. Files that may be rewritten are read strictly with no
   newline translation, edited as LF and written back with their own line
   ends. An undecodable SKILL.md is UNDECODABLE, named, exit 1; a file that
   mixes CRLF and LF is never rewritten. Read-backs compare bytes.
3. A symlinked .claude/workforce/directives led the T2 extraction out of the
   project. Any write that resolves outside the root is refused, in both
   scripts.
4. The split's proof compared tidy with the lines tidy was built from.
   prove_split now checks the rebuilt file: outside the region, the original
   non-blank lines that were not lifted, in order, plus only the template
   heading. The plan, the supplement fallback and the split are separate
   functions, and host lookups are computed once.
5. hand_kept looked for a header phrase. An index is now generated only when
   every line is generated layout, so hand sections under the old header
   survive a rebuild.

bin/check gains one assertion per finding (ulimit, CRLF and Latin-1,
symlink out and in, a splice that drops a user line, old header with hand
sections), each observed failing on HEAD, and bin/prove one mutation each.
