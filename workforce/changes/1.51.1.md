Cover the two commits that landed after the bump (v1.51.1)

`workforce/bin/wf-turn-ledger` changed after 1.51.0 was cut, and the version anchor's own
rule is that a change to any shipped file advances the number. Without this those two

Contents: the reply-fallback fix in `wf-turn-ledger` (the fallback now means what the field

This is a second bump in one session, which `wrap` discourages, and the alternative was
worse: leaving a shipped file changed with no record, which is the defect the anchor rule
names. One bump per session is about not spamming a column of version numbers, not about
letting a shipped change go unrecorded.

The reply fallback meant something the field it substitutes for does not

`wf-widen` writes `conclusion: reply` into the flag the jury reads, and the jury is asked
whether the CONCLUSION is supported. `reply` comes from `last_assistant_message`, which is
right — but the fallback for a host that does not send that field was
`"\n".join(said)`: every assistant text block in the turn. On a long turn that is dozens of
mid-turn narrations, so "what the turn told the user" became a wall of text whose middle is
indistinguishable from its end.

The fallback now takes the last non-empty block, which is what the field it substitutes for
means. Demonstrated on a constructed transcript: two assistant blocks, the first carrying a
mid-turn line and the second the real close, and `turn_counts` returns the second alone.

Guarded both ways rather than only fixed: `bin/check` fails if the reversed-scan is removed,
and a `bin/prove` case deletes it to confirm the gate notices (1 of 1 proven).

WHAT THIS DOES NOT CLAIM, and the first version of this message claimed it in its title. It
does not diagnose the jury verdicts from this session. Those refused a proposed next step —
"run the audit on odyssey-alive" — and cited the turn's own message as the evidence against
it. That was a correct veto: nothing in the turn supported the step, and no audit was run.
The flag file is cleared by `wf-task-tag` at the start of every turn, so what its
`conclusion` field held is not recoverable, and this change was authored while reading those
verdicts as a misquote rather than as a ruling. A fix found that way can still be a fix; its
commit message may not present the unverifiable reading as the cause.

This does not touch the STANDARDS the jury enforces. The instructions, gates and contracts
are what let a fresh agent be handed work and stay in its lane.

Three live failure messages named paths v1.51.0 removed

`bin/check` prints a remedy with each failure, and three of those remedies named
`evaluator-additions/` and `catalogs/text` — directories the release moved into the
shipped evaluator skills. A failure message is read at exactly the moment somebody is
lost, so one naming a path that is not there costs more than silence would.

The DEVELOPMENT.md entry describing the image/ui promotion carried the same two dead
paths and is corrected in place with a dated note; its "Still open" row was re-checked
rather than assumed — the handbook heal has still not run anywhere, because this release
ran no audit. Historical entries for earlier releases keep their original paths: that
record is append-only and describes what was true when it was written.
