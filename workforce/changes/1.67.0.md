A run that parks on a plain-text question is sent back to decide or ask with a chooser

wf-chooser is a new Stop hook, wired in the install defaults. It blocks a turn
whose final reply leaves the user a decision in prose (reply codes, "waiting on
your decision", a numbered list to choose from) and made no AskUserQuestion call.
The reason tells the run to decide what it can, finish that work, and put any
genuine decision in a chooser. A background hand-back that ends "still waiting
on your decisions" is caught the same way, so it can no longer bury the question.

Measured over 3,634 real turns: fires on 1.29%, one wrong fire. The "want me
to...?" offer class measured 4.87% and was left out. The rule also reaches
wf-task-tag's per-message context and operating-principles item 12.

Reported from an odyssey-alive /agenda today run that sat idle ~15 minutes.
