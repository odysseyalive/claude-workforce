Tracker mode, a sourcing rule, and a check before blueprint reports

A first real use of /blueprint came back with a critique: it assumed one change
implemented once, when the ask was a living tracker for a whole module.

/blueprint track writes an undated tracker with a status block, a resume
procedure, and checkboxes that tick only with evidence and strike instead of
delete. It must say which existing state record wins. Every factual claim now
cites a path, commit, or re-runnable command, or is labeled unverified, and an
unverified claim cannot justify a step. Before reporting, the plan's citations
are re-read, the project's checker runs, and a fresh agent reads it against the
evidence. The plan directory is found from where plans already live before
falling back to plan/.
