Search the user's own projects before authoring a capability (v1.14.0)

Nothing in this product ever looked outside the target project. org-design
reads the target. discovery finds the target's authoritative material. The
Sources criterion wires an employee to truth inside its own project. All of
them stop at the project boundary - and the user does not. Someone running
workforce across thirty projects is the single most likely author of the thing
being asked for.

MEASURED 2026-09-04 on pythom-space. An ask arrived through /org rung 10(b):
persist what a working session discovers so a later session can read it back.
hire was one action from authoring a new data skill - fresh tree, schema
derived from the ask, citation rule invented on the spot. The user interrupted
with one sentence naming two of their own projects. Both already carried
awareness-ledger, doing precisely this, with 78 records between them, two
maintainer scripts, a wired capture hook, and months of hardening. The
authored version would have been a thinner copy of something already working,
and no check in this product would have noticed.

  references/prior-art.md   NEW. Derives the search set mechanically from the
      workspace root rather than any hardcoded path, matches on what a skill
      DOES rather than what it is called, and returns PORT / PARTIAL / NONE.
      Carries what a PORT obliges - pick the mature copy and say how you
      decided, record every departure beside the thing it governs, re-run the
      ported checks against the new data, and fix the source too. Also what
      the step must never do: never read a sibling's data, never write to one,
      never auto-install, never treat a third-party clone as prior art.
  hire.md Step 0            NEW, BLOCKING, before the panel. A PORT hit ends
      Step 1 before it starts, because "hire or extend" presumes the thing
      must be authored and a hit says it must not be.
  hire.md Initial roster    the same search, because the greenfield batch does
      not pass through Step 1's panel and would otherwise skip it entirely -
      the one-path-only defect Core Principle 7c names.
  org-design.md step 1      prior art as EVIDENCE, so the roster is designed
      against it rather than checked after the roles are chosen.
  INV-PRIORART              row 31. NONE is reported with its denominator;
      a silent skip is indistinguishable from a search that found nothing.

hire.md's panel also gains a fourth verdict it was missing: work that is
MECHANISM - data acquisition, management, an external connection - is a skill,
not an employee. That is the user's own 2026-08-04 organizing principle, and
the panel had no row for it, so an ask for a record store had to be argued
into "neither" via the anti-bloat rule, which is about rarity and says nothing
about mechanism.
