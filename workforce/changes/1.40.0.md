Tag the ask, not the answer (v1.40.0)

ASKED FOR by the user: "how are we tagging specific tasks that are being worked on
and applying what sensory data we'll be using to achieve the score." I answered the
scoring half, described this half, and shipped nothing — then said so when asked
directly. Converting a build into a description is the same defect as stopping
mid-work, and `wf-widen` cannot see it: that turn made no promise to continue, so
there was nothing for a promise-detector to catch.

THE MEASURED MISS THIS CLOSES, from this session. Asked to decide the fate of four
scripts that live procedures still called for, the operator read `audit-setup.md`
and `invariants.md`, saw live requirements, and concluded the scripts had to be
restored. Wrong — the removal was deliberate, on the user's explicit marks, and the
commit that says so had not been read. No absence claim and no universal claim were
made, so `wf-widen` was silent and CORRECT to be silent. The reply scan had nothing
to work with. The ASK, though, was plainly a `history` question, and a history
question is closed by hearing.

SO THE TAG IS SET AT THE FRONT. `wf-task-tag` runs on `UserPromptSubmit`, which
fires before the prompt is processed and can inject context — the only point in a
turn where "which sense does this need" arrives in time to change what the turn
does rather than grade it afterwards. `wf-widen` then scores at `Stop` against that
tag instead of re-guessing from prose. The tag is the stronger of the two because it
was set before any of the answer existed, so the answer cannot have bent it.

FOUR KINDS, AND THE LIST IS SHORT BECAUSE IT IS A LIST OF MEASURED FAILURES rather
than a taxonomy of asks. Each row is a way work in this project has actually gone
wrong:

  history    why was this removed · should we restore it     -> hearing
  world      is it deprecated · what is current               -> hearing
  behaviour  does it work · why does it fail                  -> touch
  existence  is there any · how many · list every             -> taste

ALL MATCHES, NEVER FIRST MATCH. "why was it removed and does it still work" is
history AND behaviour, and both channels are required; taking the first would name
one and drop the other silently, which is the narrowing every mechanism here is
built against. Fixture `tasktag-two-kinds` proves it.

IT NAMES AND NEVER BLOCKS, asserted so it stays that way. `decision: "block"` on
`UserPromptSubmit` ERASES the user's prompt from context. Nothing about a regex
classification justifies destroying an ask, and a tagger that can swallow a prompt
on a match is a worse failure than every tunnel it prevents. The assertion is scoped
to the code below the module docstring — the docstring says the words in order to
explain why the hook never uses them, and a whole-file substring test failed on the
file DOCUMENTING the property it checks, the same shape as the producer-has-a-reader
check that once passed on its own comment.

DETERMINISTIC, NOT A MODEL CALL. Every classification is a regex over the ask. A
classifier spending a model call on every prompt to say "this one needs the web" has
to be right very often to be worth it, and nothing has measured that it would be.

ALSO IN THIS RELEASE, and found the same way — by measuring instead of assuming.
`wf-widen` had run on 8 live turns, cost 143-507ms, errored zero times, and BLOCKED
ZERO TIMES. Counting the verbs in this operator's own forward-looking sentences
explains it: `report` is the most common by a factor of three (10 uses against 3)
and was not in the detector's list. The single most frequent promise was the one
promise not detected — a guard useless without being noisy, which is the worst
failure mode because it looks fine.

Adding `report` naively would fire on correct stops, so it did not go in alone: a
CONDITIONAL promise is a wait, not a stop. "I'll report the verdict when the monitor
fires" has work pending and nothing to do; "Carrying on with that" has neither.
MEASURED over 96 tails: the widened list matches 21, handoffs take 3, the
conditional exemption takes 9 more, leaving 9 fires (9.4%) — every one a genuine
mid-work stop — and sparing 9, every one a genuine wait.
