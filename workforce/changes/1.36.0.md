Read the hooks reference and found a limit I had invented and a bug I had shipped

Prompted to check the current Claude Code documentation. Three things I had been
asserting from memory turned out to be wrong, and one of them was a live defect in
a hook wired two hours earlier.

A BUG, SHIPPED. `wf-turn-ledger`'s jargon scan read the reply out of the
transcript. The hooks reference says plainly that the transcript "is written
asynchronously and may lag the in-memory conversation, so it may not yet include
the current turn's most recent messages when a hook fires", and that a hook
needing the final assistant text "should use last_assistant_message on Stop and
SubagentStop instead of reading the transcript". So the scan could examine a turn
that did not yet contain the reply it exists to check — silently, and
indistinguishable from a clean turn. Now reads the documented field, with a
transcript fallback for hosts that do not send it. Fixture proves the lag case:
a transcript with NO assistant text and jargon only in the field.

The READ COUNT still comes from the transcript, where the lag is harmless — tool
calls are recorded before the turn ends. Only the last message is affected, which
is exactly the field provided for it.

A LIMIT I INVENTED. "The ledger is main-loop only, it will not cover spawned
agents" — reported twice as a structural constraint, never checked.
SubagentStart and SubagentStop are both documented events, and SubagentStop
carries agent_type, agent_transcript_path and last_assistant_message. The ledger
now runs there too. This matters more than the main loop: a subagent has ZERO
residency — fresh context, no history, one shot — so it is the node most exposed
to authoring from the thin surface in front of it, which is the failure this
distribution exists to name.

AND THE FIX EXPOSED A STRUCTURAL ASSUMPTION. SHIPPED_HOOKS was keyed by SCRIPT,
so one script could not be registered on two events; the key was used as a
filename and `wf-turn-ledger@subagent` resolved to a script that does not exist.
It is now keyed by REGISTRATION, with hook_script() stripping the @event suffix.
Caught by running --wire-defaults and reading its output rather than trusting the
edit.

Also recorded, not acted on: the docs list events this distribution has never
considered — PostToolBatch, PermissionDenied with a retry decision, PreModelSwitch
with a model matcher, TaskCreated/Completed, TeammateIdle, MessageDisplay,
CwdChanged. And `anthropics/claude-code` on GitHub is a README, not source; there
is no implementation to review.
