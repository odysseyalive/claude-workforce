wf-bash-stdin notes instead of rewriting, so auto mode stops refusing sibling calls

A PreToolUse rewrite of one Bash call makes auto mode refuse every later
call in the same response ("another call in this response was changed by
a hook after auto mode reviewed it"). The hook cannot see its siblings or
its position, and permissionDecision allow does not avoid it. Measured over
374 transcripts: 1.87.0 would have refused 390 correct calls. The hook now
adds its once-per-agent note in every mode and never changes input; the
1.87.0 detection and stop line remain the backstop for a hang.

Reported by the mutze-studio session: "Agents that batch Bash calls will
hit this."
