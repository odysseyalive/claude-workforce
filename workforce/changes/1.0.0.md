Initial commit: claude-workforce

Staff a Claude Code project with a company of agent employees — a CEO,
department leads, and ICs, each with an employee handbook, a pinned model,
work it will refuse, and a check that proves it.

The org is derived from what a project actually involves (layout, build and
test tooling, purpose, history). Existing skills convert in, but that is the
on-ramp rather than the road: the employees a project most needs are usually
the ones no skill ever covered. A project with no skills is the ordinary case.

Governing sources: Sam Carpenter's Work the System for the document hierarchy
(Strategic Objective -> Operating Principles -> Working Procedures, conformance
checked upward, uncovered cases falling back upward), and Boris Cherny's 2026
guidance on describing task/guardrails/exit-criteria over specifying steps,
on verification as the thing people get wrong, and on ablating instructions
each model generation.

Platform behavior is measured, not assumed. Five documented claims were tested
on Claude Code 2.1.220 before any of this was designed; three failed:

  - CONFIRMED: delegation bottoms out three layers below main, so the org is
    exactly CEO -> Lead -> IC. A deeper tier does not error, it collapses.
  - FALSIFIED: background subagents do receive the Agent tool. This had already
    been built into a blocking gate; disallowedTools: Agent is now the tier
    ceiling and background:false is advisory only.
  - FALSIFIED: neither agent definitions nor freshly installed skills are
    discoverable in the session that writes them.
  - Grep, Glob and WebFetch reach no subagent, while every MCP tool does — so
    handbooks ground in Bash, explicit Reads, and MCP servers.

references/platform.md therefore splits MEASURED from DOCUMENTED, stamps the
harness version, and bars DOCUMENTED facts from becoming blocking checks.
Constants live in exactly one file so a platform change is a small sweep, and
the three unavoidable duplication points are declared rather than hidden.

Honest limits, stated in the docs rather than papered over: the chain of
command is detection and not prevention (Agent() allowlists are discarded
inside subagent definitions, and permissions.deny has no caller axis); the
session spawn cap cannot be enforced; only the top-level summary returns.

Also fixes an inherited defect before depending on it: claude-enforcer's
backup used zip without -y, silently storing symlinked agent registrations as
file contents. Reproduced against a real 20-symlink project — 0 of 20 stored
as links, restored as forked regular files, edits to a source no longer
reaching its registration. Fixed with -y plus an in-archive symlink manifest
replayed on restore, and verified end to end.

Contents: the workforce skill (SKILL.md with six enforcement gates, 20
references, 29 procedures), four shipped panel agents, two hook pairs
(bash + PowerShell), manifest-driven installers for personal and project
scope, README and COMMANDS.

Not yet exercised: /workforce audit has never run. Tasks are open to smoke-test
it and to re-measure the two falsified facts in a fresh session.
