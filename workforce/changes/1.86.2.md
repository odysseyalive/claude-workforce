Sacred-block checksums are keyed by content, and a restamp can be scoped to one file

Each .directives.sha row is now `<sha256>  <path>`: a moved block stays
OK, an inserted or appended block is recorded alone, a stamped text that
left a file while unstamped text arrived is DRIFT and held, and a removed
block is MISSING and held. `wf-stamp --directives --execute --restamp
--file <path> --authority <AMD>` records an authorized change in one file
without re-blessing anything else. Position-keyed ledgers migrate at
session start, by --heal and by --directives --execute, carrying every
digest unchanged so existing drift stays drift.

Measured on mutze-studio: 96 of its 97 DRIFT rows were blocks that had
only moved; 1 is a real change. The old keys had also left 12 blocks with
no row.

Reported by the mutze-studio session: "an authorized insert can't be
recorded without blessing unrelated drift."
