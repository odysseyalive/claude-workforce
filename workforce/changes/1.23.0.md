Quiet is not finished, and a manager must not confuse them (v1.23.0)

wf-handoff reported this project's own finished fork as IDLE at 316,811
tokens. An agent's transcript carries no terminal record — it simply
stops — so a run that succeeded and a run that hung are byte-identical
from the file alone.

The signal is in the parent session transcript, which carries
task-notification records with a task-id and a status. read_completions
reads them; the verdict is DONE, and DONE is never IDLE.

It is a comparison, not a lookup. A resumable agent notifies more than
once, so a notice older than the transcript's last write belongs to a
stop that was then resumed — that agent is running again and must not be
silenced. Fixture handoff-done pins both halves with two agents identical
but for the order of two timestamps, and both deliberate regressions fail
exactly the case built to catch them.

This is a producer for the 2026-08-27 rule that a stuck-looking employee
is usually done-silent. A manager cleaning up on IDLE would have killed
work that had already succeeded.

Also: script-conformance gives every case an empty HOME, because
census-deadhook had been reading the maintainer's real settings and
passed only while those held no hooks; and a row missing a key now fails
that row instead of taking the run down.
