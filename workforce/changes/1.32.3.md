457 assertions had no proof case, and the number appeared nowhere

The unproven count reported last commit was wrong and this corrects it. prove's
"431 of 478" counts CASES, not assertions; 47 was cases that ran without proving.
The real figure: bin/check carries 836 assertions against 386 distinct case
names, so 457 had no case at all — more than half the suite unproven, and the
gap grew by one every time anyone wrote an assertion without also writing a case.

COVERAGE IS NOW DERIVED, NOT REMEMBERED. 278 of the 457 are one mechanical shape
— `check(name, '<literal>' in read("workforce/…"))`, or its `not in` twin. A case
for that shape is fully determined by the assertion, so prove computes it from
bin/check's syntax tree instead of waiting for someone to type it. Write a new
assertion of that shape and it is proven on the next run, with nothing to
remember. 455 written cases + 278 derived = 733.

Both polarities, and the second is not an afterthought: `'x' in FILE` breaks by
deleting x, `'x' not in FILE` breaks by appending it. An absence rule with no
case is the easier one to get wrong, because it passes on an empty file and on a
file that was never read. A del case is emitted only when the literal is present
and an append only when it is absent, so neither can be a vacuous mutation.

The longest literal is chosen deliberately. prove deletes the FIRST occurrence
only, so a short literal can be removed from a place the assertion never reads
and report a non-firing that means nothing.

THE GAP IS PRINTED NOW, ALWAYS. prove reported only on the cases it had, so it
could say "431 of 478 proven" while 457 assertions were invisible — a coverage
figure counting only what it already covers, which is this tool's own vacuous
green aimed at itself. The summary now prints assertions-with-a-case against the
total, and names the remainder as structural.

WHAT IS NOT COVERED, stated rather than left to be inferred: 179 assertions are
structural — a file exists, a count matches, a parse succeeds, two files agree.
Deleting or appending text cannot express those. They stay hand-written or
unproven, and the generator never claims them.

check 1125 passed · 0 failed · 4 skipped. The 733-case run is in flight; whether
each derived case actually fires is what it measures, and is not claimed here.
