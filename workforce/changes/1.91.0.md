wf-chooser: a pair of legends counts only in a reply that asks, and "answer with them" is not an instruction

A fourth live wrong fire, on a report describing the first fix: "tells you to
answer with them; a bare "1-4 accept, 5-6 S"". An instruction verb whose object is
a pronoun (them, it, this, that, these, those) is now a description.

The pair branch now fires only when the same tail also carries an instruction verb
or ends on a question to the reader (quotes masked). That silences every remaining
corpus match: month-day dates ("the 10-31 handoff, the 10-29 handoff"), counts
("12-15 panes ... 2-3 steps"), and a quoted question ("body = this file, face =
which file?"). A range after `$` is a price, so it is not a legend.

Cost, stated: a bare "1-4 accept, 5-6 S" with no instruction and no closing
question no longer blocks. chooser-pair-with-closing-question-blocks pins the
question path; chooser-reply-codes-blocks pins the instruction path.

Corpus (10,499 assistant texts on disk): the original rule matched 14 texts and
fired on 4 turn endings; after d3a8caf 7 and 1; now 0 and 0.

wf-catalog --restore-retired reads no link and writes through none

Security review of e4820ae, two MEDIUM findings:
- Write: the copy loop ran makedirs, then checked only whether the file's own
  parent was a link. A live `references/sub -> ../../../../outside` let the
  restore make `outside/deeper/` and write `outside/deeper/notes.md`.
- Read: the archive was walked and every entry copied with shutil.copy2, which
  follows a link. An archived `references/stolen.md -> secret.txt` put the
  secret's bytes into the project.

Both sides now use one test: a path holds no link when it resolves to itself
under the resolved project root. An archive whose path holds a link is refused
whole. A linked file or directory inside it is skipped and named. A source is
opened O_NOFOLLOW. Each path to be written is checked before any directory is
made, and the file is created O_EXCL|O_NOFOLLOW, so nothing existing is
overwritten. A file left half-written by a failure is removed.

Fixtures (both fail on e4820ae): catalog-restore-retired-link-out (exit 1,
names the refused file, outside/deeper absent) and
catalog-restore-retired-link-read (stolen.md skipped and absent, the real
file still restored).

right after the opener of five `origin: user | immutable: true` blocks

mirrors were extracted. `wf-stamp --directives` reported all five CONFLICTED
with no heal. Reproduced on b96469e against the project's pre-audit backup:

block, verbatim, to just above its opener. It does this only when what remains
equals one of the mirror's blocks byte for byte, so no word of the user's is

in the same write, and the mirror is never written. On the backup copy:
`lifted 5 · mirrored 7 · conflicted 0`, `drift 0`, and the five user blocks are
byte-identical to the project's own hand heal.

reproduce. It did not exist until e34ae0a (2026-09-06), and it has skipped
headings inside sacred spans since. The damaged files date from 2026-08-10,
and their table (`| Row | |` plus prose) is not what the script writes. Run
on the five files with the section stripped, b96469e places `## Interface`
