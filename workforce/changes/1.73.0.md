The house style for a shared artifact, and the hook that applies it unasked

USER REQUEST, 2026-10-02, verbatim: *"I would like to create a brand new skill that gets
added to the workforce installation that will go in the user directory ... I want this skill
to automatically adjust artifacts, online artifacts, especially online artifacts that are
shared. Shareable. So when a user asks to create an online artifact or workforce decides to
generate one, this skill needs to be applied so that it gets formatted correctly ... whatever
works well with workforce to make this happen automatically without being prompted."*

`shared-artifact` ships as a `sibling`, so `update` alone carries it, and `wf-artifact-style`
is wired on `PreToolUse`/`Artifact` by the same `--wire-defaults` producer every other shipped
hook uses — installer, `audit` and `verify` all carry it, so an install made before today
picks it up with nothing to type.

**The skill alone would have satisfied none of the request.** A skill that has to be invoked
is the step a long turn skips, and *"workforce decides to generate one"* happens inside a
spawned employee that never saw the user's message. `PreToolUse` fires in subagents, which is
why the mechanism is a hook and not a paragraph.

WHERE THE STYLE CAME FROM, AND WHY IT IS EVIDENCE RATHER THAN TASTE. One brief was published
twice from one session. Through the Claude Docs connector first: *"okay, the formatting of
that shared artifact is a bit hard on the eyes. Can we clean it up a bit please? Make each of
the headings pop out better and just overall appearance layed out a bit more
professionally?"* Rebuilt as one HTML page in the binder layout, the same content got *"The
new layout is wonderful"*. Both the user's own words, retained verbatim in
`references/house-style.md`, and `bin/check` fails if either is paraphrased away. The Docs
viewer owns its heading styles, so the first attempt could not make headings pop however it
was written — that is the routing rule, not a preference.

THE FLOOR IS THE SUBSET A READER LOSES THE PAGE OVER, not the recipe. `:root` colour tokens,
a `prefers-color-scheme: dark` block guarded against a forced light theme, a
`:root[data-theme="dark"]` block, an explicit `body` background, a non-empty `<title>`, and a
viewport meta where the page declares its own `<head`. Everything else in the recipe is a
quality judgement the skill makes and a script has no business adjudicating.

**The author cannot see the failure they are shipping.** You publish from one theme and the
broken state is the other one, which is the whole reason this is mechanical.

TWO OF THE ITEMS THE REQUEST NAMED ARE ADVISORY, AND BOTH WERE MEASURED INTO THAT POSITION
against the seven published artifact pages on this machine:

  viewport meta       every artifact-published page in the corpus is a FRAGMENT starting at
                      `<title>`, because the publisher supplies the document wrapper.
                      Required unconditionally, it would have DENIED the very page the user
                      called wonderful. Required only where the page owns its own `<head`.
  a width media query `krull-makeover.html`, an accepted artifact, has none: it is a
                      side-by-side of projector slides where a narrow layout means nothing.
                      Named on every publish, never a denial.

A known wrong fire is not shippable in a hook that blocks. The light-guard check gained its
SECOND accepted form the same way: `image-swap-proposal.html` lets the media block set dark
and restates the light tokens in a `:root[data-theme="light"]` rule after it, which reaches
the identical place, and the single-form check denied it. 7 of 7 now pass, 0 fire.

THREE QUADRATIC PATTERNS, FOUND BY MEASURING AND NOT BY READING. The first version read CSS
rules with `([^{}]*)\{([^{}]*)\}`, which is quadratic over a brace-free region: `findall` had
not returned after TWO MINUTES on the 456 KB `image-swap-proposal.html`, a page carrying
inline base64 images. The replacement kept `@media[^{]*(?:max|min)-width` and
`:root[^{]*\{` — a gap scan is O(n) per anchor over O(n) anchors — measured at 96.3s and
12.5s on 20,000 anchors before a 400 KB tail. Every pattern now matches inside ONE FRAGMENT
handed to it by a single brace walk: 0.06s on all three shapes, pinned by a `bin/check`
assertion with a 2s ceiling that also asserts the verdict did not change.

THE DENIAL REASON IS AN INSTRUCTION CHANNEL, AND ONLY FIXED TEXT GOES INTO IT. A
`permissionDecisionReason` is read as the model's next instruction, so the floor items are
all constants and the page's own content is never quoted — a published page legitimately
carries text from somewhere else, and "the line that failed" would be a second-order
injection straight into the instruction stream. The one outside value that reaches the reason
is the file's basename, bounded.

A detector ships with its fix: the reason names each missing item and the one action that
resolves all of them.

The starter template is derived from the reference page's STRUCTURE and CSS with placeholder
content only. The reference page is a client brief and none of its content ships. `bin/check`
runs the shipped hook against the shipped template and requires it to satisfy the floor it
enforces, because a starter that fails its own gate teaches the defect to everyone who copies
it.

Registered: a `hook` row and three `sibling` rows in `manifest.txt`, `SHIPPED_HOOKS`,
`hooks.md` § What is wired, the install count in `update.md` and `DOCTRINE.md` (seven skills
to eight). It ships a `references/` directory and is still NOT a catalog — `house-style.md`
is a recipe, not a graded corpus — so it is registered in neither `wf-catalog` nor
`wf-conform`, which is blueprint's contract and asserted here as a negative. `hooks.md`'s
paragraph on why the edit hook is `PostToolUse` said no `PreToolUse` guard ships; one does
now, and the paragraph says so rather than being left false.

Proven: 14 `script-conformance` rows including six that must NOT fire, and 8 written
`bin/prove` cases, each a semantic mutation that leaves the file parseable — a case that
breaks the syntax proves only that something reads the file.

README's shipped-skill list still names six skills and is `content-writer`'s file, not this
change's.
