The corpus moved to the install and the readers were left pointing at the copy

v1.48.0 made the evaluator corpus resolve from the install so a tweak advances by
`update` instead of by re-auditing thirteen projects. It moved the corpus and not
the READERS. `evaluators.md` still told every tier-3 IC to grep
`.claude/skills/<catalog>/references/<file>.md` — the exact files `--migrate`
removes — so the migration and the instruction pointed at each other. MEASURED:
13 governed handbooks on odyssey-alive, 5 on apps-odyssey-alive.

AN INDEPENDENT REVIEW BROKE THE FIRST ATTEMPT, and the failure is the part worth
keeping. `--migrate` never removes the skill directory, because the house rules
live in it, and `project_dir` tested only `isdir`. So a migrated project kept
answering `project` from a directory the migration had emptied. Reproduced on a
copy of security-evaluator: `project v1 · 2 file(s) · 142 line(s)`, and a grep for
SSRF returned ONE hit — the `description:` line of the surviving SKILL.md — and
EXITED 0. A hollow copy does not fail, it answers, which is quieter than the
missing path this change existed to prevent. Resolution now requires
corpus-bearing.

FOUR MORE FROM THE SAME REVIEW, each a claim the code did not perform. `norm()`
stripped a WF-ADDITIONS closing marker nothing has ever written — wf-seed writes
`… END -->` — so the one file per catalog that gets seeded could never classify
identical: 24,940 normed bytes against 9,606, reported STAYS. The additions slot
was resolved by a second independent walk and could be read from a different
install than the corpus, a state bin/check names in a failure message while
passing green. INV-CATREAD was named in two procedures and emitted by nothing.
And the detector flagged two kinds the resolver could not serve — 38% false
positives whose prescribed remedy exits 2.

THEN THE TWO UNRESOLVABLE KINDS STOPPED BEING UNRESOLVABLE. image-eval and
ui-design shipped as single seed specs: no anchor, so never reportable as stale;
no resolver entry, so `--kind image` was a parser error; not in the migration
table, so nothing reconciled the copies. ENUMERATED: 8 projects held an
image-eval, 1 a ui-design, 1 a design-eval under a third spelling, and none
carried a version anchor. Both are catalogs now, promoted by git mv with content
unchanged, and the `ui` kind maps both spellings. Five of five resolve.

Step 5d item 2c heals the citations and is EXEMPT from the refresh-due stamp,
because what endangers a citation is not the handbook's age — it is Step 6-F

Unseeded additions are reported for the first time: 6 of 12 projects holding a

every one printed `0 stale · 0 unresolved`.
