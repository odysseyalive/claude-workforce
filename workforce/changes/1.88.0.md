wf-webfetch-guard: a PreToolUse hook makes the page-fetch choice enforced per host

A security review of eea48b7 rated one gap MEDIUM. A page-fetching employee
holds both mcp__playwright-mcp and WebFetch on every host. On a host that has
the server, the only thing keeping it off WebFetch, which skips the server's
exfiltration guards, was a Guardrails line the model reads.

The new PreToolUse hook on WebFetch denies the call where playwright-mcp is
configured. Its reason names mcp__playwright-mcp__web_fetch. Where the server is
not configured, the hook allows the call. Detection is wf-web-grant.detect,
imported rather than copied, and reads config files only. The hook fails open
on any error. It is in SHIPPED_HOOKS, so wf-settings-apply --wire-defaults wires
it for the installer, audit and verify. Manifest row: hook.

Measured 2026-11-10 on Claude Code 2.1.322 with claude -p and --agents. The
hook fires on a subagent's WebFetch call (the payload carries agent_id and
agent_type), and its deny stops the call even under an allow rule. When the
hook's config has the server, WebFetch is denied and web_fetch returns "Example
Domain". When it doesn't, WebFetch is allowed. A planted always-allow copy let
the call through. Recorded in platform.md fact 4, which also says how strong
each layer is: the hook enforces, the Guardrails line is advisory.

not move.
