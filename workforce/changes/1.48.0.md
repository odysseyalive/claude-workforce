THE USER'S CORRECTION, and it lands: "If you don't see 'the audit process should

That message produced the migration classifier. Calling it an instruction rather

READING BETWEEN THE LINES IS NOT A REGEX PROBLEM, and the attempt to make it one
was already measured and rejected in the previous commit: unhedged `should be`
doubled the tagging rate by catching plain instructions. Widening a pattern until
it reads intent is how a guard arrives at the false-positive rate that gets it
switched off.

SO THE FIX IS TO STOP RELYING ON CLASSIFICATION TO DECIDE WHETHER ANYONE CHECKS
THE WORK. A share of UNCLASSIFIED turns is now read by someone who did not do it.
Same argument the existing 1-in-5 audit of PASSING turns already makes — "auditing
only the turns that fail their own dispatch is the self-scoring bias wearing a
different hat" — extended to the turns no pattern classified, which exited at line
550 before the sampler and could never be audited at all.

TWO THINGS HAD TO CHANGE FOR THAT TO BE POSSIBLE:

`wf-task-tag` DELETED its tag on an untagged prompt. That fixed a real staleness
bug and created a worse one: `Stop` then had no `prompt`, and the jury correctly
refuses a case with no ask — so an unclassified turn was unauditable by
construction. It now writes an explicitly-empty tag, which clears staleness just as
well because it IS this turn's, and keeps the ask on disk.

The docket is ASSIGNED, never inferred — `e83990e` forbids inferring one, and for
good reason: a jury handed an empty case convicted twice. `smell` and `intuition`
are the two senses needing no particular channel, and `senses.md` says intuition is
deliberately unscored precisely because judging one's own prior from inside is the
impaired faculty. From outside it is readable. That is the standing docket.

The corpus was one text and a copy per project made it nine

MEASURED across thirteen projects on this machine, twenty catalog copies. The
shipped text catalog stamps `creative-scrub-ref-version: 2`; its copies stamp
2, 1, 2, 2, 1, absent, 2, 1, absent, and their `additions-seeded` records sit at
none, 6, 6, 7 and 7. Six states of one corpus. The per-project copy exists to
prevent two canonical texts and produced six.

THE CAUSE IS THE THREE-PATHS RULE FAILING ON THE CORPUS ITSELF. A copy is written
at `audit` and refreshed only by a later audit OF THAT PROJECT, while `update`
advances the install and reaches none of them. A project nobody re-audits is
frozen at whatever shipped the day it was staffed.

`wf-catalog` resolves the corpus from the install: one copy, advanced by `update`,
reachable from any project — including this repository under `workforce dev`,
which has no org and so could previously reach no catalog at all. The HOUSE RULES
do not move: the supersession register and the precedence clause are the genuinely
project-specific layer, and `audit` already refreshed them separately every run.
This moves the half that was never local. Resolution is PROJECT-FIRST, so a
project holding a copy keeps being answered from it byte for byte.

Wired on three paths, because a mechanism that arrives any other way does not
propagate: the install ships the corpus, `audit` Step 6-F migrates a project onto
it, `verify` reports a project still reading a copy — including `STALE (install is
vN)` and `no version anchor`, the two states invisible from inside a project.

THE MIGRATION IS THE SECOND DESIGN. The first compared HEADINGS AND TABLE ROWS and
removed a whole copy on a pass. An independent code evaluation broke it the day it
was written, in one move: append a prose project rule under an existing heading —
"never flag anything under `legacy/vendor-shim/` as dead". No new heading, no new
row, so the copy classified as pure residue — and `residue` then rmtree'd the
skill, taking CATALOG-ANCHOR.md (the house rules and register this change exists
to LEAVE local), the handbooks, and hook scripts that had been excluded from the
walk and therefore read by nothing. Every gate protecting that verdict was a
chance to fail open and three of them did: a sacred marker with one trailing space
was invisible, a symlinked copy raised out of the middle of the destructive loop,
and a malformed settings file turned the run into a traceback.

So removal is per FILE and the proof is byte identity — the install ships a file
of that name and the two match once the machine-owned additions region, the
version anchor and trailing whitespace are normalised away. Everything else stays.
The skill directory is never removed at all, so the register, the handbooks, the
scripts and the hooks survive by construction rather than by gates that each had a
chance to fail open. Unremovable is the default; identity is the only thing that
lifts it.

The hook registrations are a REFUSAL, not a warning, and they read project AND
user scope: a registration in ~/.claude naming $CLAUDE_PROJECT_DIR/.claude/skills/
<evaluator>/ is exactly what the refusal exists to catch. Measured live the same
day — hither-lands and apps-odyssey-alive register three such hooks each, and
odyssey-alive carries `chain-image-eval.sh` TWICE on PostToolUse, which is the
double activation this migration exists to end rather than to create.
