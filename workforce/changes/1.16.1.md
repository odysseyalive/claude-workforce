A bare `-mcp` slug is a word, not an invocation (v1.16.1)

wf-conform's body-vs-grant coherence check read both forms an MCP server can be
named in prose - the tool prefix `mcp__<server>__<tool>` and the bare slug
`<name>-mcp` - and treated them as equally strong evidence. The prefix is an
invocation. The bare slug is a word, and three things in an ordinary tree are
spelled exactly like a server and are not one.

MEASURED 2026-09-05 by /workforce verify on playwright-mcp: 5 blocking failures
across 5 of 6 handbooks, and all 5 were the same two words.

  build-mcp        a project SKILL, reached through Skill(). It appears only as
                   `.claude/skills/build-mcp/SKILL.md`, a path, in 4 handbooks.
  playwright-mcp   the repository's own name. It is in every absolute path its
                   handbooks quote and in the sentence saying what the employee
                   maintains. The two employees that genuinely drive a browser
                   already granted mcp__playwright-mcp.

The org was correct and the gate was red. verify.md § BLOCKING forbids a report
arguing a failure away in prose - "either wf-conform marks the row advisory or
the row is a failure" - so a run hitting this had no legal move: it could not
discount the count, and it could not grant `mcp__build-mcp` for a server that
does not exist. The project had already recorded it as a deferred row rather
than fixing it, which is the standing-queue shape the 2026-08-10 directive
refuses.

The exclusion is structural, made once, where a fixture can prove it fires.
Three cases drop a slug from the WEAK form only:

  the slug resolves to `.claude/skills/<slug>/SKILL.md` in either scope
  the slug equals os.path.basename(root) - the project's own name
  the slug sits inside a path, `/<slug>` or `<slug>/`

ONE-SIDED, deliberately. MCP_TOOL_RX is untouched, so an employee that writes
mcp__foo-mcp__thing is still caught even where the slug is also its project's
name. The residual miss is a project named after a server it consumes and never
invokes by tool name - one advisory-grade gap, against a BLOCKING false positive
on every project whose own name ends in -mcp.

Four fixtures, one per exclusion plus the negative:

  conform-mcp-slug-is-skill      helper-mcp resolves as a skill      exit 0
  conform-slug-is-project-mcp    the fixture dir IS the project name exit 0
  conform-mcp-slug-in-path       /home/u/lab/widget-mcp/src/...      exit 0
  conform-mcp-slug-bare          none of the three apply             exit 1

The negative is the load-bearing one. Without it the exclusions could be widened
to nothing and every fixture would stay green - a check discounted into silence
is the same failure one layer down.

conform-mcp-ungranted is unchanged and still red: it names the server as
mcp__playwright-mcp__web_fetch, the invocation form, which no exclusion touches.
