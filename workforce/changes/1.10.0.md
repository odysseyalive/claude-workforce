judgment roles: a gate is calibrated against the principal, not only its catalog (v1.10.0)

A design gate returned PASS-WITH-NOTES on every home-page build it graded across four
rejection cycles, and the principal rejected the result every time. It DID block twice
in that span -- always on catalogued MSG/CTA/A11Y rules; it has never once blocked on
thinness or on image absence, which is what the principal rejects. Nothing in the org
could see the disagreement. The
catalog's five image rules all passed on a page with zero images -- one tests broken
images, one tests whether imagery is filler, one tests AI tells in imagery -- because
a rule written against a thing that exists cannot fire on its absence. So the cheapest
way for the doer to clear an image finding was to delete the image, and removal never
fails a rule.

The doctrine that produced it is verification.md's tier table: tier 4 is "judging
against a catalog -- catalogued rather than tasteful", and "review the output for
quality" is rejected at authoring time. That is right for code, tests, records and
security, and it has no category for a role whose deliverable IS a judgment. Applied
there it does not raise rigor; it removes the gate's ability to report anything its
catalog does not already name.

INV-EVALS's escape hatch is MEASURED, not read. As first drafted it was satisfied by
the exact state that motivated it: one judgment role, zero eval sets, zero PERFs, six
unrecorded rejections -- "no principal verdict exists yet" was true, so the row would
have printed UPHELD over the silence. The hatch now opens only when the gate has
produced ZERO reports under work/. A gate with reports on disk, no PERFs and no eval
set has not escaped; that IS the disagreement going unrecorded. Absence of PERF
records may never be read as absence of disagreement -- telling those two apart is the
row's whole job.

The framework already had the category and withheld it from one class of employee:
procedure-for-procedures.md gives Leads no ## Procedure because "their job is
judgment". The same argument reaches an IC whose job is also judgment; what it does
not reach is verification, which is why this is a different check and not no check.
