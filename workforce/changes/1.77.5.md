The turn a dispatched item finishes on is the turn that can finish it

MEASURED 2026-10-13 in odyssey-alive's session `629732ff`, which the user was
looking at: *"the job looks like it's done, but the ISSUES item doesn't appear
to be updating."* Turn 1 was the `/org` calendar ask — one item written, an
agent dispatched, "handed off" replied, and the Stop ended the turn with the
item correctly open. TURN 2 WAS THE HAND-BACK, which arrives as a user message
beginning "Another Claude session sent a message" and so matches `INJECTED`:
`start_checklist` absorbed the outgoing list, removed the file, and returned
before writing a new one. The session's own `sed` to mark the item done
answered "No such file or directory", the Stop found no record to absorb, and
`i1 KICKBACK 1 of 1 items unaddressed` printed about finished work, on every
Stop afterwards.

1.77.4's carry reached only a turn that opened a checklist of its own, and the
turn on which asynchronous work finishes is exactly an injected one — so an
issue whose agent reports after its turn ended could never close, and neither
could one finished by a reply as short as "yes it's done".

So a message that opens no list of its own now gets the file and the carried
rows anyway, with `items` empty and no ask-splitting asked of it, and gets
nothing at all when this session has nothing open. The record is marked
`carry_only`: `wf-widen` reads the carried statuses back at that turn's Stop
and closes the issue, and hands the widening jury NOTHING for that turn,
because an injected hand-back is not the user's ask and must not be graded as
one. The record names no issue either — the next message's `absorb_items`
would otherwise copy its empty `items` over that issue's real items.

The two context sentences now have one definition each, since both lines say
them. `bin/check`'s pin on the carried words stays honest that way, and the
two checklist-staleness assertions ask what the file HOLDS rather than whether
it exists, which is what they were always about: a carry-only file is not last
turn's list.

Three fixtures hold the states and `bin/check` runs the whole five-event
sequence, because a fixture case runs one invocation and this defect only
existed across a Stop.
