A generated component catalog first, then the asks checklist without its block

The user: "I would rather simpler the better ... I think you really overbuilt
my ask", then, on removing pieces safely: "each of the different components
that we build need to be catalogued ... to check ... that we're not pulling out
mechanisms that run other things", "a list system ... that gets updated after
each change we make", and "maybe this should be pushed to the front of the
work order?"

bin/components (maintainer tooling, not shipped) builds the catalog from the
code on every run: each shipped hook and exec script, each per-session
hand-off file and the agent hook, with the imports, shared functions, calls,
file roles, JSON fields, registrations, prove cases and docs that connect
them. It shares its role logic with bin/check rather than copying it. bin/check
fails on any component that depends on something that no longer exists, and
bin/prove --since prints the dependents of what changed before its cases run.
Its stated limit: coupling that runs through no shared file, function, import,
call or field. One old dangling edge is on record and warned:
wf-claude-md still loads the removed wf-standing-request.

Then the simplification, checked against it. Removed: the Stop-time checklist
block (both reasons, as_data quoting, the plan-mode exemption, item_closed)
and wf-commitments' count against the checklist. Kept: the checklist file and
a shorter injected line that no longer promises a send-back, the notification
keep-rule and the once marker (renamed enforced -> ended; the catalog shows the
juror depends on both), the loop bound, reply confirmation. Changed: the asks
juror is handed the list when the tag counted 2+ asks OR the file has 2+ items,
and its prompt seats on an empty list; a Stop whose reply is not confirmed
judges nothing at all; a side query's Stop removes a flag only after the Stop
that raised it has finished (its stop_hook_summary row is newer than the flag),
so the agent never judges one flag twice. workforce/bin is 53 lines shorter
(15,482 -> 15,429).

65 of 65 bin/prove cases PROVEN on the changed files. bin/check 1255 passed, 0
failed after sync. Replayed by the operator: a "push it" Stop returns only the
not-judged note with no flag; the real Stop with two open items is not sent
back for the checklist and hands both items to the jury with the real reply.

Hooks judge a reply only when the transcript shows it was the reply

Claude Code sometimes hands Stop hooks a `last_assistant_message` that is not
the final reply. MEASURED: "push it" twice and "commit and push it", all prompts
the user has typed before and consistent with prompt suggestions, plus "Reading
wf-widen and wf-commitments", which reads like a background progress summary.
None of them occurs as message text in any transcript. wf-widen stored them as
the flag's conclusion, and the widening agent blocked on text the user never
saw: the first bad block of the claude-enforcer loop, and a false block on a
`/workforce dev wrap` turn.

`confirmed_reply` in wf-turn-ledger is now the only reader of the field. The
payload counts only when it equals the transcript's last assistant line after
whitespace normalization; on a mismatch it re-reads once after 500ms (the host
writes the transcript on a 100ms timer). If it still does not match, nothing
judges or records it: wf-widen skips the promise check, the claim scans, both
samples and every flag, and prints the reply length; wf-commitments records
nothing. The tag's sense check and the asks checklist still run, since neither
reads the reply. With the field absent, the fallback takes only text after the
last tool call, because the old fallback always picked an earlier narration.
SubagentStop confirms against agent_transcript_path.

False-positive measurement: 0 of 1,069 real final replies on this machine are
rejected by the rule. Five bin/check assertions run the hooks (side-query text,
genuine reply, late transcript row, SubagentStop, missing field), six bin/prove
cases break them, and eleven fixture transcripts now end with the reply as a
real host writes it, their expected outputs unchanged. Built by
engineering-coder, work order org-reply-verify-20260913T154020Z.

Replayed by the operator: a "push it" payload writes no flag and prints the
note; the genuine reply writes the flag with the real conclusion. bin/check
1253 passed, 0 failed after sync.
