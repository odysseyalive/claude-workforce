Handoffs and job folders save to the folder the session started in, even your home folder, without asking

A session started in your home folder asked whether to save a handoff "in the
user scope, ~/.claude": with the project at ~, the project's .claude is also the
default account's config folder. The handoff and working-files skills now say
the folder the session started in is the project, even when it is ~, so the
handoff goes to ~/.claude/workforce/jobs, which every account starting in ~
reads whatever CLAUDE_CONFIG_DIR it uses, and is saved there without asking the
user to pick a scope or an account (i16).

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>

Wiring a project that is your home folder no longer reports every hook as firing twice

With the project at $HOME and CLAUDE_CONFIG_DIR unset, project scope and user
scope are one folder, ~/.claude, and the project's settings file can be the user
file itself. `--wire-defaults` wrote nothing twice, but its double-firing report
read that one file once per scope and printed "registered at BOTH user and
project scope" for every default hook. The count now reads a file once, so a
hook wired once is reported once, and a real duplicate row is still reported.

Case: sa-wire-home-one-folder-counts-once (i16).

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>

User-scope wiring lands in your account's settings, whatever folder you run it from

Running `wf-settings-apply --scope user --wire-defaults` from your home folder
under a second account (CLAUDE_CONFIG_DIR=~/.claude-brooke) read ~/.claude, the
default account's settings, as if it were a project. Every hook it found there
was reported "already registered" and the second account was left unwired,
with exit 0. User scope has no project, so the working directory's .claude is no
longer read at all: the presence check, the scope-collapse note and the
double-firing count all look at the account's own settings file only.

bin/script-conformance gains a `cwd` row key so a case can run a script from a
directory inside its tree; sa-wire-user-from-home-second-account uses it (i16).
