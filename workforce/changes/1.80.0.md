Release 1.80.0: text-eval catches empty maxims, buried points, bare statistics and US defaults

User, 2026-10-16: "we have a text evaluator with workforce. Please review the
following youtube transcript and see if there would be anything beneficial to
making the text evaluator better at its job" ... "please make a blueprint" ...
"okay, build it. when it's ready, wrap things up and commit to main".

Plan: plan/text-eval-transcript-additions-2026-10-16.md. All catalog content
lands in workforce's own additions.md (text-additions-version 7 -> 8); the
vendored text-tells.md, version.md and human-markers.md are untouched.

- Insight-shaped line: a maxim in body prose that fails a paraphrase test (no
  concrete who-does-what) or an opposition test (nobody would argue the
  opposite). Judgment class, not [hard], so deliberate aphorism can be demoted.
- Cultural-default examples: illustrative choices (foods, holidays, public
  figures, brands) drift to the US default against a stated context elsewhere.
  Grounded in Agarwal et al., CHI 2025 (arXiv 2409.11360), added to Provenance.
  Idiom stays with Locale mismatch so the two rows don't double-count.
- Unsourced specific: a bare statistic, date, quote, study or case with no
  source. SHOULD FIX at one occurrence where the venue expects sources, which
  overrides the cluster rule there; CONSIDER elsewhere. Lists, never verifies.
- Sharpened tests for shipped rows: Heady abstraction gains a compress-to-
  about-eight-words test beside its own.
- Workflow: step 1 builds a claim inventory; new step 2 restates the point in
  one plain sentence before the catalog is read. A point that can't be
  restated is one CONSIDER counted toward the cluster. Reports open with both.
- The drift-anchor check is now `grep -l ... | wc -l`. `grep -c` printed one
  count per file (0, 4, 1, 0) and never the "2" its comment promised.

Demonstrated, each evaluation in a fresh isolated agent reading the repo copy:
a planted 176-word sample fired all four new rows on the right sentences, with
the statistic at CONSIDER for a blog venue; the user's own words as a control
fired none of them; the shipped probe still returns the [hard] em-dash and the
MUST FIX cluster. A bin/dev-sandbox install shipped both files byte-identical
and was removed. An independent diff review found no defects; a text-eval of
the new prose found two em-dashes on rewritten lines, an unclear sentence, a
reference giving the wrong reason, and a compression example that added a
claim. All fixed here.
