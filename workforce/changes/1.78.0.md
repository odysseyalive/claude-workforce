  prints it before the status. No title written, none invented.
- An issue with agents working shows `PROCESSING` and a count, never a list.

  message whose items all continue earlier issues folds into them. A fold

  items of its own.

  harness's subagents/agent-<id>.meta.json), else the newest.

  forever (three issues held for hours on 2026-10-14).
- The checklist lands on its issue at its own Stop instead of a turn later,
  gated like track_message so a side query never absorbs a half-written list.

Demonstrated on throwaway projects, real hooks: title + PROCESSING · 1 agent
working; follow-up folded into i1; a reviewer naming i1 linked there though i2
was newest; a killed coder dropped the count to 1. Planted defects: linking to

Audit puts every model-pinned agent on the model its lane selects

User, 2026-10-14: "when we run audit, all agents that are marked with
claude-opus-5 should automatically be bumped to claude-opus-5-5", then: "I'd
rather audit do this dynamically be examining the description of each of the

Measured that day: this repository's engineering-coder spent ~57M tokens in two
weeks on claude-opus-5, three weeks after the code lane moved; the same stale

New shipped script wf-model-lanes: enumerates every model-pinned file under a
project's .claude/ (agents, skill-bundled agents, skills), resolves each lane's
model and effort from org-config.md (employee override, then lane, then tier),

with a description hash so only a changed description is re-judged, and
rewrites only the model:/effort: lines that differ, writing through symlinks.
Shipped files and links leaving the project are reported, never written. An
employee override matches by name or file name; one that matches nobody stops
the write rather than letting the lane default replace the user's pin. audit
runs it every time (Step 6-M); verify reports drift; model-map and invariants
(INV-LANES) describe it. Shipped pins: deadcode-gardener to the code lane,
image-validator to creative-visual.

Demonstrated, not gated: on a scratch copy of ~/lab/hither-lands with a stale
claude-opus-5 pin planted, the plan flagged it OFF-LINEUP, execute moved only

and a typo'd row both silently lost the user's effort before; now the first

SHIP; its override-matching note is the fix above.

ISSUES tracks a turn the session never itemized, under the user's own message

User, 2026-10-14: "I really like how you are tracking ISSUES ... in a session I
have running in ~/lab/odyssey-alive, I don't see the ISSUES tracking text there."
Then: "I'd like that. it gives transparency on what is being worked on."

Measured in odyssey-alive session a609a11d: `/agenda today` wrote no asks list,
the issue had no items, judge_issue returned `open`, and ISSUES printed nothing
for two hours.

At the Stop ending a user message's turn, an issue with no session-written items,
no agents and an empty checklist records the message itself as one item marked
`fallback`. It shows as a new `tracked` verdict and can never reach kickback,
handoff or escalate: every failing verdict reads `session_items`, which excludes
it. The next turn is handed it as a carried row to mark; an unmarked fallback is
`superseded` when the next user message's turn ends. Injected turns supersede
nothing. A typed slash command now opens an issue at any length.

Verified the new way, without bin/check or bin/prove: the real hooks run on a
throwaway project through three turns (/agenda -> TRACKED; marked done -> CLOSED;
task-notification -> no fallback, a session-written open item still KICKBACKs),
0.35 s; plus an independent reviewer read of the diff (SHIP).
