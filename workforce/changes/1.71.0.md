A citation counts where the path it writes would actually resolve

The first pass at the citation guard matched a bare basename from anywhere, and on a real
project that is nearly everything: `image-eval/SKILL.md` "cited by
.claude/agents/bible-scholar.md:41 … (+502 more)" — every mention of any SKILL.md in the
tree; image-eval's `references/ai-patterns.md` held by an agent reading TEXT-EVAL's file
of the same name; `references/templates.md` held by awareness-ledger's own templates. A
copy that can never retire breaks the 2026-09-10 directive as surely as one that retires
what a reader needs.

Matched the way a path resolves now. From INSIDE the copy, `references/x.md` and a bare
`x.md` both count — that is how `image-eval/references/invocation.md` links
`output-formats.md`. From OUTSIDE, only a citation naming the skill does: `<skill>/<rel>`,
which `.claude/skills/<skill>/<rel>` and `~/.claude/skills/<skill>/<rel>` both contain.

AND A RECORD IS NOT A READER. `.claude/workforce/deferred.md` and
`.claude/.symlink-manifest.txt` were holding files on the strength of a queue quoting the
paths it complains about. The rule lives beside `SACRED_SCRATCH` in wf-census, its owner,
as a rule rather than today's filenames: under `.claude/`, a tool's own output — a
`.json`/`.sha`/`.lock` scan or sidecar, anything named `manifest`, and the two prose
records a run writes. `grounding/`, `recruiting/`, `personnel/` and `directives/` are
deliberately not in it: an employee reads them.

Measured on a copy of a real project's `.claude`, migrate display, before → after: the
kept SET is the same 33, because every kept file also had one citation that truly resolves
— what changed is that all 24 cited entries now name a reader that does. The +502 lists
are gone, and image-eval's ai-patterns.md and templates.md rest on their own readers
instead of two other skills'.

A quoted grep pattern is a pattern, not a dead file

`candidate_tokens` split every fenced and backticked line on whitespace and threw the
quoting away, so a grep PATTERN shaped like a path — `grep -c
"security-ref-version/catalog.md" references/security-taxonomy.md` — passed
`is_file_reference` on its `.md` tail, resolved against the tree, and printed `! dead`.
Greping for a path-shaped string is an ordinary check, and the report told its author to
create a file that was never meant to exist. Reported 2026-09-25 from
audit-20260925T180537Z.

The pattern is dropped by POSITION — the first non-option argument of a pattern-taking
command — which covers the quoted and unquoted spellings alike and can never eat a real
path, because the pattern slot cannot hold one. `-f/--file` keeps its path AND fills the
pattern slot; `--` ends the options; a pipeline is read as the several commands it is.

The option table is GREP's, so it is spelled `grep --regexp` and `bin/check`'s flag-lie
scan is widened to accept a string that names the command whose flag it carries — the
same exemption it already makes for `claude` and `wf-*`. Proven still to catch the class
it exists for: `"pass --run to execute every match"` names no other command and still
fails.

fixtures/scripts/checkrun-grep-pattern. Against HEAD's wf-checkrun: `! dead
security-ref-version/catalog.md`. Now: the pattern is gone and the file argument still

A journal row whose path is a path is checked, whether or not the directory is still there

`check_journal` decided aggregate-ness from DISK — `os.path.isdir(path_cell)` — and the
false answer to that question is the defect the check exists for. A T7/T7s row with a
typo'd path, and a swept skill whose directory is gone BY DESIGN, both read as "an
aggregate row (undo is the backup)" and had their `.orig` and prior-sha compared against
nothing. Reported 2026-09-25 from audit-20260925T180537Z.

The row's SHAPE decides it now: a cell with no spaces, unparenthesised, carrying a
separator or an extension is a path and is always checked; `(all skills)` and
`scaffolding blocks` are not and still pass as aggregates.

Making the check fire surfaced the second half: the single-file undo is RELOCATED by the
sweep exactly as the whole-directory one is, and this lookup was hard-coded to
`staging/<name>/SKILL.md.orig`. `undo_orig` searches where `undo_tree` searches — its own
candidate list, one directory up — so a correctly swept target with its `.orig` under
`work/<run-id>/staging/` is not called absent.
