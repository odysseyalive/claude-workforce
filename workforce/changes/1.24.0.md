Bound the report, not just the return line (v1.24.0)

Both `## Reporting` contracts capped the RETURN LINE at three lines and said
nothing about the length of the OUTPUT.md being written to disk. Nothing
downstream ever told a report to stop.

Measured on apps.odysseyalive.com 2026-09-07, window opening 2026-08-13:
454 reports averaging 225 lines — 102,297 lines of report against 46,315
lines of application source. The org had written more than twice as much
prose about building the product as the product contains. Every single
report is individually reasonable, which is why no run ever looked like the
problem: it is a missing constraint in a template, inherited by every
project the skill has ever staffed.

The bound is an ADDITION to the block, never a replacement of it. Three
existing rules live in these same lines and each is asserted separately —
the REQUEST echo-back (check:9954), the command-prefix refusal that came
out of the odyssey-alive incident (check:663), and the no-REQUEST QUESTION
rule. A wholesale rewrite of `## Reporting` reds those checks instead of
this one, and the new assertion's failure message says so.

The budget DERIVES rather than being picked: an IC gets three lines of
evidence per exit criterion, a CEO adds three per subordinate report it
integrated. An IC proving four criteria and a CEO integrating six reports
are not the same artifact, so one flat number would be wrong in both
directions.

Existing orgs pick this up through `audit` Step 5d, which already refreshes
handbooks against the installed contract and rides the `workforce-version:`
stamp. No explicit amend needed, and no new propagation path.

Not adopted from the same proposal: suspending audits while a module is
built. That is deferred self-correction, and the 2026-08-10 directive rules
it out — no blocks, no exceptions. Per-phase dispatch and per-phase record
stamping are project cadence, not template work.
