wf-map --tests lists the test files named after the file: test-<name>, <name>.test, test_<name> and the other conventions, beside it or in a test directory

--tests never looked for a test file. It read this repository's expectations.json
and handbook rows only, so in e2e-proof-mcp `--tests scripts/merge-codex.mjs` did
not name scripts/test-merge-codex.mjs beside it. A new group lists files whose
NAME says they test the target, found by listing directories, with nothing opened
or run: the file's own directory, a test/tests/__tests__/spec/specs directory under
it or an ancestor (flat or mirrored), and the path with one component swapped for a
test directory (src/main/java -> src/test/java). The extension is ignored.

Fixtures: map-tests-sibling-test-files, map-tests-test-dirs-and-mirrors,
map-tests-maven-mirror, each with near misses that must not be listed.

wf-conform reads a hyphenated MCP server whole: a slug no longer starts at the hyphen inside mcp__e2e-proof-mcp

MCP_SLUG_RX opened on \b, which fires at a hyphen, so `mcp__e2e-proof-mcp` also
yielded the slug `proof-mcp` and the body-vs-grant row reported a server nobody
named as missing. Three odyssey-alive handbooks failed it on 1.95.0. The slug now
opens on (?<![-\w]), so it never starts after a hyphen or inside a mcp__ token.

Fixtures: conform-mcp-hyphenated-server-not-misread (granted servers pass) and
conform-mcp-hyphenated-server-still-needs-a-grant (an ungranted my-widget-mcp
still fails, named alone).
