Release guard reads variables in execution order; closes the 47d46b1 regressions

The 47d46b1 guard kept the last assignment to a name on the line, so `v=push; git $v;
v=status` read as `git status`, and `for`, `export`/`declare`/`local`, `+=` and indexed values
resolved to nothing and were allowed. Its zsh glob-group branch also swallowed `case x in (x)
git push` and `for x (a) git push`. Each of these was denied by 4d4fa50.

Now segments are classified in order and each name carries its possible values: an assignment
that may not run (after && or ||, inside if/loop/case, a pipeline stage) adds a value instead of
replacing one, and any release among them denies. Subshells, $(…) bodies and child shells
restore values on exit; eval keeps them. A substitution is read when its command runs, including
those inside ${…}, arithmetic and unquoted heredocs. An unresolved or $(…) command word has the
rest read as a command with its own words, so `$X git push`, `c="git push"; $c` and
`b=push; $(echo git) $b` deny. `function f { … }` bodies are read. Values and combinations are
capped at 50, failing closed past it. guard-corpus reports a guard exception per command
instead of crashing.

Still a documented limit: a verb in a variable assigned outside the line (`git $V`).

Measured: deny-check 383 cases, 0 wrong. guard-corpus 29,009 commands, 0 unexpected; 1 of
28,615 distinct corpus commands moves (deny to allow, a grep/echo check string run through
bash -c). Baseline replay 20261016T005640Z: 0 commands change decision.
