Four cases that pass are not a test suite (v1.21.2)

The peer session reviewing v1.21.1 said the case worth a prove row is the
one with competing user values, not the clean tree. Correct. I had
verified that behaviour by hand, once, in a scratch directory -- and this
repository's own harness says a fixture that works once is not a
regression test, it is a single observation.

Four fixtures, and only the first discriminates. saunwire-userhook seeds
the user's OWN Stop hook and a wf-plain-guard on a matcher the record does
not name. saunwire-absentstyle has output_style_previous null.
saunwire-userchanged has a style the user picked after ours.
saunwire-norecord has no sidecar at all. A clean tree proves nothing here:
every implementation passes it.

Then two deliberate regressions, because four cases that pass with no
evidence any of them CAN fail is still four observations. "Remove by event
alone" fails saunwire-userhook on the missing Edit matcher. "Write a
default back" fails saunwire-absentstyle. Each failed exactly the case
that should catch it.

Two things found while landing it:

  The fixtures were UNTRACKED and would have been absent from every
  clone. A common global ignore excludes **/.claude/settings.local.json,
  and a settings file is exactly what these fixtures are. .gitignore
  already carried an anchored note about this same failure one directory
  shallower -- twelve fixtures committed as descriptions of content that
  was never in the repo, found by cloning. This is that, at
  fixtures/scripts/<name>/.claude/.

  bin/check CRASHED rather than failing. A prove mutation left
  expectations.json mid-edit and a bare json.loads took the whole file
  down, so every assertion became unrunnable because one input was
  malformed -- strictly worse than the check it guarded. A check that
  cannot parse its input fails that check.
