The auditing agent caught a contradiction the author could not see (v1.44.1)

FOUND BY `wf-widen-agent` ON ITS FIRST REAL OUTING, hours after being built and one
release after being pointed at judging results. It read a hand-off that said

    unopened: ["touch"]        evidence.channels.touch: 24     ran: 24

and refused to judge, because the input contradicted itself. That is the correct
refusal: an evaluator that guesses which half of an incoherent input to believe is
worse than one that reports the incoherence. And it is the independence directive
paying for itself within a day — the session that WROTE both fields saw no
contradiction at all, because it had written each of them for a different reason and
never read them side by side.

THE BUG. `raise_flag` derived `unopened` from the `why` rows it was handed, and `main`
narrowed those rows with `[... if sn in unopened] or why`. On a SAMPLED turn nothing is
unopened, so the list is empty, so the `or why` fallback substitutes the FULL applicable
set — and the flag then reported every sense the ask required as unopened, including
ones the turn had opened twenty-four times. `unopened` is passed in now and never
inferred, asserted so it stays that way, with a fixture pinning the blocked direction.

WHAT THIS SAYS ABOUT THE ARCHITECTURE, recorded because it is the first evidence either
way. The redesign's claim was that a reader which did not do the work sees things the
author cannot. The first thing it looked at was a defect the author had shipped in the
same release that built it, in a file the author had read a dozen times that hour. It
did not find it by being smarter; it found it by reading two fields together that the
author had only ever written apart.
