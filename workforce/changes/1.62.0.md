Weigh the user's own words newest first, and never re-offer an old decision against a new ask

An interview of the apps-odyssey-alive session found why it answered "the home
page doesn't have any data there for the DocuSign" with a menu whose Recommended
option left the card looking the same. A grounding employee reported an August
owner decision as a standing constraint ("Widening or superseding it is the
CEO's call"), rung 6f's plan gate sent "owner decisions needed" to the user, and
nothing said the user's request that day outranked the old record. Rung 14
already forbade a menu that includes stopping; it lost to a report that framed
the old state as something the user had to reopen.

The user stated the rule as a directive, in three messages, captured verbatim in
SKILL.md: evidence is weighed by date, latest first, the current chat included;
what counts is the user's own requests and notes, not an AI's interpretation of
them; and projects already mark that difference.

Carried by /org rung 14 and 6f, operating-principles item 12, and both ## Sources
sections of the handbook template, so the employee reading the records applies
it as well as the session reading the report. An older decision a newer ask
contradicts is superseded, stated in one line, and never put back on the menu;
no option delivering less than the ask is marked Recommended.

Heal: /org dispatch and operating principles are copies in each org, so an
existing project picks this up at its next audit.
