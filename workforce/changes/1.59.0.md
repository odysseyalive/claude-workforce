install.ps1 installs the sibling evaluators and ports the kept-slot and prune rules

install.ps1 parsed six of the nine manifest flags. It took each `sibling`,
`exec-sibling` and `agent` row's whole text as the path and fetched
`$RepoUrl/sibling workforce/skills/...`. Measured under pwsh 7.6.6 against HEAD's
port: 19 FETCH FAILED lines on a two-evaluator manifest, and no sibling, agent
registration or record. Every Windows install since the evaluators became siblings
(2026-09-10) failed to fetch all five evaluators and their agents.

install.ps1:
- One flag table and parser feed the fetch, prune and verify passes. Destinations
  match `install`: siblings beside skills/workforce, `agent` rows as <agents>/<dir>.md.
- Sibling ownership is decided once per skill, on its SKILL.md, against a snapshot of
  .installed-external taken before the first write.
- A kept evaluator that still has corpus receives only additions.md, where the file is
  absent or recorded, never through a link. Exactly the placed paths are recorded.
- The prune is ported: rule 1 inside the skill directory, rule 2 by record with kept
  skills carried forward, the retired-list bootstrap, and no prune after a failed
  fetch. A file that will not delete is named and the run goes on, as with `rm -f`.
- A file:// repo URL is copied. pwsh 7's Invoke-WebRequest rejects the scheme, so the
  documented test seam had never run on the port.
- verify reads with `Get-Item -Force`. Without it, pwsh on Linux and macOS threw on
  .immutable.sha and ended the run after the prune.

Where parity is not exact, and why:
- Windows has no executable bit. Under pwsh on Linux or macOS the bit is set at fetch;
  verify does not repair it afterwards the way `install` does.
- A link is a reparse point: symbolic links and junctions, but also cloud placeholder
  files such as OneDrive's, which are therefore refused a slot.
- Recorded paths are normalized with GetFullPath, so they use backslashes on Windows,
  which is what wf-catalog's os.path.join comparison needs. On Linux they are
  byte-identical to the bash installer's.
- The prune's deletion whitelists compare paths case-insensitively, because on Windows
  two spellings name one file.
- Unverified on Windows PowerShell 5.1 itself: the port was run under pwsh 7.6.6 on
  Linux only.

bin/check:
- install.ps1 parses every flag the bash installer parses, reading both sets off the
  files, and both installers parse every flag manifest.txt uses. Failed first against
  HEAD: missing agent, exec-sibling, sibling.
- manifest.txt's header documents every such flag. Failed first: the header omitted the

- With PowerShell on PATH or named by WF_PWSH, the kept-slot probe also runs
  install.ps1 through the same shapes, plus a fresh sibling, an agent registration and

  PowerShell checks fail.

bin/prove: 9 cases for the four checks. The PowerShell cases report N/A where no
PowerShell exists rather than VACUOUS.

manifest.txt: the header documents sibling, exec-sibling and agent.

Proof, all with a throwaway HOME:

  0 failed, 6 skipped.
- A full-manifest install by each installer: both exit 0, print Verified 207/207, and

Detect references that outlive a swept skill, and run the count after every sweep

A peer host on 1.58.0 swept skill-builder on 2026-08-10, and four audits later seven
live instructions still named it: two hook messages ("Run /skill-builder code-eval
create", "use /skill-builder inline"), three paths into its deleted references/, and a
SKILL.md naming `/skill-builder code-eval enforce`. audit.md § After the sweep required
the rewrite, but nothing counted what survived, and `wf-remainder --dead-scripts` and
wf-conform read clean every run.

`wf-remainder --root <tree> --swept-refs` is the detector. The swept set comes from the
records the sweep already writes. A skill counts as swept when a COMMITTED T8 sweep row
names it (parsed by wf-conform's swept_undo_paths, loaded rather than copied), a
COMMITTED row names its `.claude/skills/<name>` directory, and its SKILL.md is not back
on disk. It scans .claude/ skills, agents, hooks and scripts for `/<name>`, and for
`.claude/skills/<name>/...` paths that no longer exist. Each row is LIVE, USER-SPAN
(reported, never edited) or SHIPPED (the distribution's file, which update would
overwrite). It exits 1 on any LIVE row.

audit.md § After the sweep runs it on every audit that reaches Step 6c, including one
that swept nothing this run. Every run's sweep rows count, so a re-audit heals residue
an earlier sweep left. LIVE rows are rewritten by the section's table and the step is
not finished while the detector exits 1.

Shipped evaluator files: the vendored code-evaluator/references/version.md:62 names
`/skill-builder code-eval enforce` in a dated changelog entry. It is byte-identical to
its claude-enforcer origin and is left unedited under the vendored contract; the
detector reports it as SHIPPED.

Proof: fixtures remainder-swept-refs (5 live, exit 1; HEAD has no such mode) and
remainder-swept-refs-rewritten (0 live, exit 0), with decoys for a hyphenated
command, a bare word, a non-skill sweep row and a surviving data path. A bin/check
assertion and prove case pin the audit wiring.

Kept evaluators receive workforce's additions slot; the personal root resolves

DEF-Q-011/012, one root cause, measured at a peer host on 1.58.0 whose project root is
$HOME. Its four customized evaluators pre-dated the install, so `install` kept them and
skipped every shipped file, `references/additions.md` included, which is workforce's own
authored slot rather than vendored corpus. No copy existed under ~/.claude:
`wf-seed --execute` failed `additions slot not found` on every audit, and from /tmp
`wf-catalog --kind code|text|security|ui --path` answered unresolved because
`install_dir` ownership-tested the personal skills root and rejected the kept copies.

install: a kept sibling still receives its slot file, and only that. It is placed only
into a skill that still bears corpus, only where the file is absent or the pre-run record
says the installer wrote it, and never through a symlinked skill directory, references/
or file. Exactly the placed paths are recorded, so the kept SKILL.md stays unrecorded
and a later `update` refreshes the slot. A 1.58.0 host heals on its next update with no
manual step. bin/sync carries the same rule, so a synced sandbox matches an install.

wf-catalog: the personal skills root is not ownership-tested. That test separates a
project copy from the install at their shared path, and no project copy exists there.
This subsumes the scope-collapse special case. `corpus_files` no longer reads
`additions.md` twice now that the slot sits inside references/.

wf-seed: the slot-not-found error names the paths it tried and the remedy.

Proof: bin/check probes run the shipped installer in throwaway HOMEs across three shapes
(kept corpus, project-own slot plus a retired shell, symlinked skill) including the
refresh run, with five prove cases breaking each clause. Two new wf-catalog fixtures
reproduce the unresolved answer and the double read against HEAD's script.

Recruiter freshness: a current web dossier satisfies a re-audit's forced research

recruiter.md § Cache and freshness rule 1 reused a `sourced: web` dossier inside the
90-day window, while § In audit's remediation and audit.md Step 5c forced fresh research
on every role. A re-audit holding 8- and 18-day-old web dossiers could not satisfy both.

Both docs now state the resolution their own stated reason gives: the forcing exists
because the handbook's bar proved wrong, so the bar is what is never trusted. A web
dossier inside the window IS fresh research and satisfies Step 5c; a seed, stale or
absent dossier triggers new research. Each file points at the other.
