39 of 54 vacuous verdicts were one bug: deleting the first copy of two

The 733-case run finished: 667 proven, 54 VACUOUS, 9 SETUP-FAIL, 3 STALE-CASE.
The vacuous ones are the serious class — an assertion that did NOT fail when the
thing it names was broken — so each was read rather than counted.

39 of the 54 are a single defect in the generator, not 39 weak assertions. A
derived case asserts `'lit' in <whole file>` and prove's `del` removed the FIRST
occurrence only, so a literal appearing twice survived the mutation and the
assertion stayed true. `delall` is added and derived cases use it; hand-written
cases keep first-occurrence semantics, because those name one site deliberately.

Caught it on an assertion written the same afternoon — `a retired hook is
UNWIRED by the same pass that wires the live ones` came back vacuous because its
longest literal, `_same_command(h, command, root)`, also appears in
do_unwire_defaults.

THE STALE-CASE DETECTOR WAS SCOPED TOO NARROW and missed 12 rows on its first
real run. It scanned only `workforce/`, so cases naming `manifest.txt`,
`fixtures/scripts/expectations.json` and `.claude/` state walked past it — the
same too-narrow shape the symlink refusal had to be widened out of. It is now
keyed on the case MODE rather than the path's shape, which is what a 4-tuple has
and a name or payload cannot fake; requiring a "/" had excluded `manifest.txt`,
a bare filename, where six of them lived. `.claude/` stays excluded on purpose:
its absence here is a decision, so those are reported by prove for a human to
read rather than failing a commit for a correctly missing file.

9 more residue rows removed, all naming assertions bin/check no longer has.
446 written + 278 derived = 724 cases.

check 1126 passed · 0 failed · 4 skipped. The remaining 15 vacuous verdicts are
not explained by the delall fix and are not claimed as fixed; the rerun measures
which of them survive.
