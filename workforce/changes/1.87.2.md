A backgrounded command that left stdin open is named the moment it backgrounds

wf-bash-stdin@background on PostToolUse/Bash: when the result carries
backgroundTaskId and the command contains `<`, one note names the shell,
says its stdin is an open socket, and gives wf-widen's own stop line with
the shell's output file. It never changes input. Measured over 374
transcripts: 173 such commands, 116 of which hung or ended only by a kill
(1.49 warnings per hang); on the timeout path 79% of `<` commands hung
against 26% without.
