An interpreter's inline script is read from any leading option, not only an exact -c

wf-census decided an inline script only when tokens[1] was exactly `-c` or
`-Command`. A handbook Check `node -e "require('./lib/x.js')"` or
`bash -ec 'test -f references/a.md'` therefore named its code as the script and
wf-checkrun blocked on a dead check. Found while fixing university--11; not an
inbox row.

The leading options are now walked per interpreter: a sh/bash/zsh short cluster
holding `c`, a python cluster reaching `c`, node `-e/--eval/-p/--print`, and
pwsh `-Command/-c` are inline. Option arguments are skipped, so
`python3 -W ignore script.py` resolves `script.py`, not `ignore`. perl and ruby
stay undecidable.

wf-checkrun reads quoting, so a quoted pattern is never a dead file

Closes upstream row university #11 ("`wf-checkrun` can read a quoted grep
pattern as a path"). The 2026-09-25 position rule held only while the
pattern was one whitespace word with no `|`: `grep -c "old guide/intro.md"`
and `grep -E "legacy|refs/x.md"` still produced dead rows, and so did sed
and awk scripts, jq filters, find -path patterns, python3 -c and bash -c
bodies, and `grep -m 1` (the count was taken as the pattern).

Words are now split by shlex with punctuation_chars, and each command's
arguments are read by its own option grammar (ARG_GRAMMAR). A quoted FILE
argument is still a path, a quoted "$(...)" is re-read as a line, and the
Guardrails pass now examines a quoted command word.

Regression fixture: fixtures/scripts/checkrun-quoted-pattern. HEAD printed
13 dead rows on it, 11 invented; this prints the 3 real ones.
