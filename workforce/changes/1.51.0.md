The corpus shipped to the install and the five skills stayed behind

v1.48.0 moved the evaluator CORPUS into the workforce install so a tweak advances by
`update`. It left the five SKILLS per-project. MEASURED 2026-09-10: `~/.claude/skills`
held `workforce` alone while `odyssey-alive/.claude/skills` held all five. `update` ran,
verified 368/368 files, and reached none of them; three of five kinds then resolved from a
stale project copy and the shipped corpus reached no reader there. A corpus that advances
under a skill that does not is not a propagation path.

THE USER DIRECTIVE, captured verbatim in SKILL.md § Directives: "the five evaluations and
workforce should be self-contained in the user during install so that I don't have to run
an audit every time there are changes. All I have to do is update workforce", and "the
audit of a project removes the old ones of the project so that the one in the user space is
the one that's being used ... No exceptions." Its second clause is about HOW an ask is
answered: the run had already delivered a narrower version of it and offered that back as a
menu. A stated ask is not a starting point to negotiate down from.

`text-eval`, `code-evaluator`, `security-evaluator`, `image-eval` and `ui-design` now ship
as SIBLINGS of `skills/workforce/` — each complete, its `references/` IS the shipped corpus,
and `agent` rows register the four bundled agents where the host reads them. A nested
`AGENT.md` is not auto-discovered and is not a filename the host registers; shipping the
definition and registering it are two rows over one file. Resolution is INSTALL-FIRST,
which reverses v1.48.0: project-first meant a stale local copy beat a current install and
`update` could never change that. All 13 projects on this machine now read 5 of 5 from the
install, without an audit.

RETIREMENT IS UNCONDITIONAL, SO THE SAFEGUARDS MOVED. Every earlier design kept a file by
PROVING it redundant, and the proof was also the preservation — identity by basename left
three of five kinds at `keep-all` with ZERO basename overlap, so no content either side
could hold would ever have changed the verdict. Now `audit` Step 6-F lifts every
`origin: user` span into `CATALOG-ANCHOR.md` and READS IT BACK, and archives the whole
removed set under `.claude/workforce/retired/`, before one file goes. Either failing is
blocking. What survives is make-before-break, not exception: the house rules, and any
agent, script or hook the shipped evaluator does not itself ship.

AN INDEPENDENT REVIEW BROKE THE INSTALLER, and that is the finding worth keeping. The
ownership guard read `.installed-external` live while the fetch loop wrote into the same
tree, so row 1 installed `SKILL.md` and every later row read that just-written file as
proof the skill was the project's own. A fresh install shipped ONE file per evaluator under
`Verified: 195/195 files present`, and never self-healed. The guard now reads a snapshot
taken before the first write. The same defect was live in `bin/sync` — which is where it
reached the real personal install — and `bin/dev-sandbox` builds its sandbox with
`bin/sync`, so every local test exercised the tool that had the bug and never `install`.

Three more from that review: a prune branch printed "keeping the project's own skill" and
then deleted its recorded files; the `origin: user` pattern required the two fields in one
ORDER, so a reversed marker was invisible and its words would have gone silently; and a
project-only `scripts/` or `hooks/` file had no make-before-break protection.

`bin/check` DIED ON AN EMPTY FILE rather than failing. The security-anchor assertion indexed
`splitlines()[0]`, so a `bin/prove` case that empties a file to confirm the gate notices
took the whole 736-case sweep down with an IndexError instead of producing a failing case.
A diagnostic must not die on the input it exists to diagnose.

Gates: `bin/check` 1202 passed / 0 failed; `bin/script-conformance` 212 of 212, including
three catalog cases rewritten to pin the new contract; `bin/prove` 733 of 733 proven by
breaking, 0 VACUOUS, 0 BAD-CASE.
