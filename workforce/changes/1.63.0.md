Rank original human code above AI code, and say which is which at the edit

The user's directive, same day as the user-words rule: existing code has
precedent over what the AI devises, and original human code has more precedent
than AI code layered on top of it, even newer AI code. Without that, new code
arrives in the AI's default style instead of the project's mechanisms, helpers,
error handling, naming and comments.

USER_WORDS in wf-task-tag now carries the order: the user's newest words decide
what; original human code decides how, newest first; AI code already in the
project comes next; the AI's own preferences last. Precedent covers style and
mechanism, not bugs, and on a mostly-AI project the user's words are the human
precedent. It reaches the session on every message and every spawned agent.

New hook wf-code-origin (PreToolUse, Edit|Write|MultiEdit|NotebookEdit) reports
before the edit which lines of the file are human, AI, or unknown, from git, not
style: a Claude Code marker is AI, a commit before the repo's first marked commit
is human, an unmarked commit after it is unknown until the user settles it once
in .claude/code-origin.json (161 such commits measured in odyssey-alive). A new
file gets the human-created files beside it. Context only, silent outside git,
Python 3.6 safe, no cache left in /tmp.

bin/check builds a real repository with one commit of each origin and asserts the
split, the note, the new-file case, and that a spawned agent hears the order.
Everything ships in the install and update wires it: no audit.
