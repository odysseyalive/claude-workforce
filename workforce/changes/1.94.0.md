A background shell that hangs is reported STALLED with what it is blocked on, and the agent that owns it resolves it

wf-bg-watch starts beside every background shell (through the existing
wf-bash-stdin@background hook) and samples its process tree every 30 s. A shell
that has used under 1% CPU, done almost no I/O and written no output for ten
minutes is flagged STALLED, with a diagnosis: process states and wait channels,
a stdin nobody writes to, open connections, an unreaped child, the last output
lines. A busy or printing job, a listening server, a file watcher or a timed
sleep is never flagged, however long it runs. A timeout is not the fix: it is a
guess, and it says nothing while the job hangs.

The flag reaches the agent that started the shell, which stops it and reruns
with the cause fixed or reports why not. The main session asks that agent
through SendMessage and brings the user a chooser (stop, keep waiting, rerun)
for what it cannot fix. Nobody relays a waiting notice as is (i18).
