Resume the agent a turn cap cut, instead of waiting on work nobody will finish

cut run ended with the manager holding no instruction — and the instruction the
session reached for was a fresh agent of the same role, which starts the work over.

MEASURED the same day: resuming a cut coder with `SendMessage` kept its whole context
and gave it a fresh turn allowance — one cut at 80 tool uses finished at 129.

So one state, written at one end and acted on at the other:

* `wf-turn-budget`, at its final threshold, marks the agent `handoff` on its issue
  through `wf-task-tag`'s own ledger API (`agent_handoff`), never a second writer. It
  marks it there because that is where the `agent_id` and the count are known;
  whether `SubagentStop` fires when the harness cuts a run at `maxTurns` is
  unmeasured, and a mark waiting on an unmeasured event is the same silence one layer
  in. The import is local to that path: loading the sibling costs a measured +35 ms,
  and this hook runs on every tool call of every session.
* The MAIN `Stop` in `wf-widen` judges an issue holding a `handoff` agent with UNMET
  items as unfinished, and says the one action: RESUME that agent_id with
  SendMessage, continuing from its own HANDOFF.md. It never names a successor.
  `judge_issue` no longer HOLDS on a `handoff` agent — that was right while nobody
  set the state and is now a wait for a run the harness has already ended.
* The loop guard is PROGRESS, not a count. `agent_handoff` fingerprints the issue's
  UNMET set; a second mark carrying the digest the first one left means the resumed
  agent handed off again with nothing moved, and the entry is flagged
  `handoff_stalled` so the Stop escalates to the user with the agent's own HANDOFF
  section 1 instead of asking for a third resume. No agent can be escalated before it
  has actually been resumed once.
* An all-MET `handoff` agent closes its issue and is retired to `returned`, which is
  the half that holds when the cap stops the run before `SubagentStop` fires.
* The once-only claim is keyed by ROUND. The count is cumulative across a resume and
  the marker lives under the same session and agent, so a round-blind claim was spent
