org log: the runtime surface diagnose never had (v1.11.0)

diagnose exists to measure whether workforce is still fit to staff other projects,
and every surface it read was STATIC -- audit --review, verify, preflight,
invariants.md. Not one of them observed a run. So the failures a deployed org
actually suffers -- a Lead dispatching at the wrong rung, an IC reporting PASS on a
check it never ran, an agent burning its turn limit and needing a resume -- reached
the command whose job is finding them only if a human noticed and said so. The audit
process was being corrected from documents rather than from what happened.

  org.md          the receptionist's `log` mode. `/org log <ask>` dispatches exactly
                  as /org would with telemetry on; `/org log` alone reads back and
                  writes nothing. Append-only .claude/workforce/telemetry/<run-id>.jsonl,
                  rows: spawn (off the .spawn edge rung 1 already requires at every
                  depth), return (dur_ms/tool_uses/subagent_tokens verbatim from the
                  harness's own usage block, plus verdict, checks_declared vs
                  checks_run, writes_outside_scope), and operator -- the rejected
                  question, the interrupt, the turn-limit resume, which leave no trace
                  in any artifact because the finished OUTPUT.md looks identical
                  either way.
  diagnose.md     the fifth surface and the four lenses it is read through:
                  inefficiency, orchestrator error, agent malfunction, failure. Each
                  names a defect whose fix is a step, an invariant, a budget or a
                  scope line -- a lens that yields "try harder" is not a lens. The
                  project is named with --telemetry <path>, repeatable, never
                  discovered. Absent telemetry is NOT MEASURED naming the path.
  templates.md    log is a GENERATED mode of the receptionist. Hand-added, it is
                  erased at the next org index and the loop stops silently.
  bin/check       10 assertions pairing each rule with its wiring.
  bin/prove       17 cases -- 9 for this change and 8 for v1.10.0's calibration
                  tier, which shipped UNPROVEN. prove keeps a hand-maintained
                  case list, so an assertion added to bin/check is not proven
                  by adding it; v1.10.0 reported check-green as if that settled
                  it and it did not. Each case deletes one load-bearing literal
                  and asserts the paired check fires.

THE EMITTER RECORDS AND NEVER ASSESSES. Every field is copied from something that
already exists; nothing is scored. The moment a field means "was this good" the
emitter is a judgment role and owes a calibration check (verification.md, v1.10.0) --
which is the trap this release cycle just spent its length escaping. Classification
belongs to diagnose, which owns the vocabulary findings are named against.

Telemetry stays in the project. No ~/.claude collection point and no registry of
installs: both re-create the shadowing failure bin/sync documents, where a stale or
foreign copy silently becomes the thing that gets read.

Two things this buys immediately. The org's own recorded defect -- measured
2026-09-01, 252 edges, mean 3.5 lines, 2% carrying exit criteria -- becomes a query
instead of a bespoke investigation. And work/ becomes collapsible: a run whose
telemetry row exists and whose captures no eval case cites is reclaimable, the row
surviving and the megabytes not. That is the standing answer to a work/ tree at 190M
and to the tension evals.md otherwise creates by arguing those captures must be kept
forever.
