A version number nothing could explain (v1.31.0)

ASKED FOR by the user during `/workforce update`: "does every version number come
with some kind of file that says okay this is the change that happened during this
version number?" It did not. `update` printed `1.28.0 -> 1.30.3` and stopped.
`audit` — which minutes earlier had gained the ability to read an org's chart stamp
and see it was behind — had nothing to consult about what "behind" meant. Two
commands could see a number move and neither could say what moved with it.

The user named the constraint before it was hit: "we don't want a huge file loaded
in the context as the project grows ... some kind of skill-based query of changes,
where there is an index and only the MD files for that particular version are what
is pulled." That is the right shape and the numbers say so. MEASURED: DEVELOPMENT.md
is 213,761 B — 2.7x the SKILL.md that the strip removed for being too large to sit
at the head of every turn. A flat shipped changelog hands every project a
quarter-megabyte to answer a question that usually spans two releases.

SHAPE. `workforce/changes/index.md` is 4.7 KB, one row per release, always readable.
One body per version beside it, pulled only when a range asks for it. Total on disk
161 KB across 35 files, of which a typical query reads the index and two bodies.
`wf-changes` does the pulling and is a SCRIPT, not an agent, per the second
directive: data in hand that answers the question is itself a terminal answer. An
employee can call it and gets the same bytes; what an employee adds is what to do
about them.

DERIVED, NEVER AUTHORED, which is what keeps it from rotting. Bodies are the commit
messages between one bump and the next — already ~2.4 KB of why-this-changed prose
that nobody would write twice. `Surface` comes from the PATHS a release's commits
touched, so it cannot drift from the change. `Org: yes/no` says whether an existing
org holds a COPY of something the release changed: a handbook contract, the chart
format, the /org dispatch checkpoint, the operating principles. `yes` means
installing the skill was not the whole update.

READERS, because a record nothing queries is a documentation folder. `update` step 7
prints the range and names `audit` when any row needs a heal. `audit` Step 5d runs
`wf-changes --from <chart stamp> --heal-only`, so it applies the deltas of the
releases that need them rather than every heal pass on the strength of a version
number. Both are asserted, along with the query being shipped at all.

TWO COLLISIONS, each resolved rather than worked around.

`bin/pre-commit-version` refuses a bump whose changes/<new>.md is absent, and the
generator derives releases from committed history — so at the moment the record is
needed, the commit that would create it does not exist. That deadlocks every future
release. Resolved by a PENDING entry classified from the uncommitted diff, which is
exactly the change about to ship; the next regeneration rewrites it from the real
commit, because this tree regenerates whole rather than appending.

The archive is verbatim history, so the authored-prose rules invert on it. An old
message legitimately names a command a later release removed — that is what the
message is FOR. A paragraph repeated across two commits is two days' writing, not a
duplicate to collapse. And the only way to satisfy `constants: stated once` would be
to EDIT the messages, which is rewriting history to pass a style check against the
directive that the record is retained. Excluded by prefix in ONE place with the
argument written beside it, never by growing five exemption sets — an exclusion that
spreads is how it ends up covering files nobody argued for.

Also capped: the first release's body walked back to the repo root at 679,219 B, 87%
of the whole record, for the one release nobody upgrades FROM. It now carries its own
bump commit and says where the rest is. A 60 KB per-body ceiling truncates LOUDLY,
naming the git command that shows the remainder.

bin/check 1079 -> 1118 passed, same 5 pre-existing failures. All 181 script fixtures
pass, including 5 new ones for wf-changes covering a range, a heal-only filter, an
empty range, a chart with a stamp, and a chart without one.
