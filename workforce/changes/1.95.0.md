Web access survives the playwright-mcp to e2e-proof-mcp rename: every grant, guard and check accepts both server names

The playwright-mcp server is being renamed to e2e-proof-mcp, same server and same tool names, so
every tool moves from mcp__playwright-mcp__* to mcp__e2e-proof-mcp__* when its installer runs on
the three Claude accounts. Until every machine has switched, claude-workforce accepts both.

- wf-web-grant knows both names. A governed handbook whose tools: or disallowedTools: names one
  gets the other beside it, at server and tool level, so browser_* testers and deny entries follow
  the rename too. Nothing is removed and order is kept, so a second run is a no-op.
- wf-webfetch-guard denies WebFetch under either name and points at the web_fetch the host has.
- wf-conform treats the two names as one server for the body-vs-grant row; an unrelated server
  still fails.
- The handbook template, procedures and references grant and name both prefixes.

Proven by 12 new script-conformance cases (old-only, new-only and both-name installs, the guard
under each name, conform aliasing) that fail against 1.94.0's scripts; 916/916 pass.

The old name is dropped in a later release.
