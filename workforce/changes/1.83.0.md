Installer pre-allows its own update command, so update runs without a prompt

The installer now writes an exact-match permissions.allow rule for the update
command of the scope it installed (`-- --user` to the user settings.json,
`-- --project` to .claude/settings.local.json). In default permission mode the
command was blocked without one, so `/workforce update` handed it back to the
user to paste. Audit's --wire-defaults re-adds it; verify reports it absent.
The rule string lives once in wf-settings-apply, and script-conformance fails
if it drifts from update.md step 4. Measured on Claude Code 2.1.314 (platform
fact 29). install.ps1 skips it: the PowerShell rule form is unmeasured.
