Release 1.76.0: ui-design designs a surface before it grades one

/ui-design direct runs before the first UI build. It reads the project's CSS stack, asks
only the case questions the files leave open, classifies each screen by the job it does
against a new situation-keyed ergonomics catalog, finds free references that fit the stack
and the job, and puts them on a shareable page where people comment before the user picks.
The choices land in .claude/design/direction.md, which builds and BF-02 reviews read.

Give ui-design a direction half, so a surface is designed before it is graded

`review` and `sweep` can only speak once the page exists, when the remedy they can
ask for is a reskin. Nothing gathered references, asked about the case, or picked a
direction first, so a builder designed from model memory and landed on the model's
average page — the state SLOP-02 catches too late and BF-01 had no durable brief to
grade against.

`direct` is that missing step. It reads the project's CSS stack from its own files,
asks at most four case questions in ONE AskUserQuestion call and only the ones the
project left unanswered, classifies every screen by the job it does, searches the
stack's own template and block sources before any gallery, presents the candidates in
the session artifact as screenshots with links for people to review and comment on,
reads those comments before asking for the pick, and writes the project's design
record at `.claude/design/direction.md`.

Two reference files land, both cited from sources fetched 2026-10-08:

- `direction.md` — the procedure, the stack-detection table, the per-stack source list
  with free-and-capturable separated from link-only, the licence note per source, the
  request hygiene (few requests per host, a block is a skip and never a retry, keep
  Preline's trailing slash), the review round, the no-artifact-tool and no-browser
  fallbacks, and the design-record template.
- `ergonomics-catalog.md` — 46 `ERG-<SITUATION>-NN` rules over eight situations
  (LAND, FORM, TRIAGE, JOB, DASH, COMPARE, READ, SET), each with severity, Basis tag
  and a fetched source, plus the "Classifying a screen" section both halves key on, a
  Source Ledger naming its two blocked fetches, and an append-only growth region.

Where the two catalogs meet, the new one CROSS-REFERENCES the existing row rather
than restating it: VH-01..07, TYP-02, CTA-05/06/07, MSG-*, SLOP-05 stay canonical
where they are, and reporting one defect against both would double its count.

`design-quality-catalog.md` gains BF-02 in its growth region — a UI-shipping surface
has a design record, and the render matches the references and refusals it names — and
its title broadens from marketing and landing pages to rendered interfaces. No existing
row is reworded, per that file's own header rule.

Uniqueness comes from the inputs for the case at hand, and nothing compares one
project's design to another's: "It's not about comparing project to project. That's
not practical, it's about asking the right questions to pull in specific direction for
the case at hand."

Read the pre-mutation bytes, so a vacuous assertion stops reading BAD-CASE

The order was written against a009bda's conclusion that a `del` case whose
literal occurs once can never return PROVEN. MEASURED 2026-10-08 by running it,
on a copy of this tree with that pin reverted to a bare presence test: it
returns PROVEN. `prove_one` tests `name in fails` before anything else, so a
failure the mutation manufactured cannot demote an assertion that fired.

What the manufactured failure really cost is the OTHER verdict. When the named
assertion does NOT fire — a genuinely VACUOUS one — the dead-case scan's own
failure makes `fails` non-empty and the row comes back BAD-CASE: "the mutation
broke the file, retarget your case" in place of "this assertion tests nothing".
That is precisely the confusion those two labels were split apart to end, and it
reached every hand-written del case whose literal occurs once. Measured on the
org-sync cycle case, staged vacuous: BAD-CASE, on one other failure, and that
failure was the dead-case scan reading the sabotage.

So prove parks the pre-mutation bytes outside the copy and hands the child their
path in WF_PROVE_PRISTINE; bin/check's dead-case scan reads the file as it SHIPS
through `_as_shipped`. The scan keeps its teeth — a case naming a literal the
shipped file lacks still fails it, which is the residue it exists for.
