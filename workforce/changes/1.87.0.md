Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>

Background shells: every host phrasing is detected, the close-out names a stop that works, and stdin is closed

wf-widen reads a backgrounded command's id from toolUseResult.backgroundTaskId
first and falls back to all four host phrasings (measured over 374
transcripts: 783/311/272/42), so output before the phrase no longer hides
a start. The close-out gives each open shell a stop line that works with
Bash alone (holders of its output file via lsof/fuser, kill the process
group) and says never `pkill -f <id>`; an agent's close-out is recorded
apart from the parent's, so the parent's next Stop names a shell the agent
left behind.

New wf-bash-stdin PreToolUse hook: the host closes a command's stdin unless
its text contains `<`, so such a command can hang on any stdin reader
(measured: mutze `ls` -> eza). In auto mode it prefixes `exec </dev/null`;
in other modes the permission check would refuse the rewrite, so it adds a
once-per-agent note instead. Wired through --wire-defaults.

On mutze agent a49f3cb4a3a631a6f the change detects 9 of 9 backgrounded
shells (HEAD: 3).

Reported by the mutze-studio session: "Producer asked me to report this and
have you patch whatever is workforce's."
