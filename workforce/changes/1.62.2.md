Give spawned employees the user-words rule too, on SubagentStart

1.62.1 put the newest-first rule for the user's own words into wf-task-tag on
UserPromptSubmit, which reaches the main session on every message. A spawned
agent never sees that context, and the case that started this was an employee's
report framing an old owner decision as locked.

wf-task-tag is now registered a second time as wf-task-tag@subagent on
SubagentStart and there emits USER_WORDS only, before the widen-flag clearing so
a mid-turn spawn does not drop the main session's flag. One text, one script, two
events. The 2.1.268 binary's SubagentStart branch reads
hookSpecificOutput.additionalContext. It is a default hook, so the installer wires
it and update, which re-runs the installer, carries it to every machine without
an audit.
