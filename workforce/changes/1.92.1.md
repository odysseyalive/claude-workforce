Memory saved for your home folder is no longer offered to every project under it

A session started in ~ saves Claude memory under the home folder's store, and wf-memory read
that store as memory of every project below ~. Personal-machine notes (audio, printers,
trading) were listed as uncarried rules and the session was told to run reconcile-memory over
them (issue i14).

- Memory saved for $HOME or any folder above it is never read: not by --scan, the
  session-start note, or the save-time note. A project whose root is $HOME still reads its own.
- Memory saved for a parent folder below that (a session started in ~/lab) is another folder's
  memory. --scan lists it in its own section, uncounted; no note names it, and reconcile-memory
  carries one only when the user asks.
- This project's own memory, in every ~/.claude* account, is read as before.

reconcile-memory's table and step 1, and the hooks and audit references, say the same. Five new
script-conformance cases cover the home store, a parent folder, the project's own store, and a
project rooted at $HOME.
