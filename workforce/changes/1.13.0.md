audit instruments itself (v1.13.0)

The most complex multi-agent run this skill performs had no runtime instrumentation.
report.md says what a run CONCLUDED; nothing said how it got there.

Every spawn now appends a `spawn` row and every return a `return` row to
.claude/workforce/telemetry/<run-id>.jsonl, in the same act that writes the .spawn
edge and in the schema org.md § The receptionist's `log` mode already defines -- one
format, because dev diagnose reads them all through one set of lenses. The EDGES
ledger carries the count:

  EDGES  7 spawns this run · 7 edge files recorded · 14 telemetry rows · 0 unrecorded

Normally twice the spawn count, so a shortfall names which returns never arrived,
which is itself the finding. No new invariant row: EDGES already owned audit's spawn
accounting and this extends it.

ALWAYS ON here, unlike /org log. Ordinary dispatch is frequent and the flag keeps it
cheap; an audit is rare, deliberate, already writes a durable report.md, and asking a
maintainer to remember a flag on the one run most worth instrumenting gets it
remembered exactly never.

What it records that report.md structurally cannot: dur_ms, tool_uses,
checks_declared against checks_run, and the operator rows for an interrupt or a
turn-limit resume. MEASURED 2026-09-03 on a real project -- a records agent hit its
40-turn limit mid-run, was resumed, and finished correctly, and no artifact anywhere
shows it happened. A resumed partial result and a clean one-pass result return work
that looks identical, so the report faithfully records the wrong thing.

diagnose.md also names `audit-*` run-ids as audits instrumenting themselves: the
highest-value rows it reads, because an audit's inefficiency and agent-malfunction
signals are the PACKAGE's, not the project's.

One of these four assertions shipped VACUOUS and bin/prove caught it. `"telemetry
rows" in _ai_aud` stayed true after the ledger line was deleted, because the prose
explaining the line still contained the phrase -- so bin/check was green on that
assertion the whole time it was testing nothing. It is bound to the EDGES LINE now,
with the reason recorded beside it. Worth stating: that is the same defect as a design
gate passing six builds it never really examined, authored three commits into fixing
that exact pattern. Knowing about the trap does not stop you falling into it; only
breaking the check does.
