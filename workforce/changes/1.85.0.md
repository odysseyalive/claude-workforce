Work list shows every open issue, partition guidance gets a Stop check, and the widen flag judges the turn it belongs to

Reported from tmux-revive (session ca202cd9) at the user's request: "I noticed that you're not making use of any agents and are dealing with all of these issues in one stream ... I'm also not seeing a list of work items to denote that you are tracking each of these asks separately."

Three defects, each reproduced on a throwaway project before the fix and planted back out after it.

1. Partition guidance was advisory text and nothing read it back. In that session it was ignored on eight turns (i13, i14, i26, i28, i30, i33-i35). wf-widen now runs worked_inline() at the main Stop. It fires on 3+ session-written open items across 2+ issues, with no agent on them, a turn that wrote files (checklist edits excluded, judged per Bash segment by bash_writes), and no Agent, Task or SendMessage call. It prints an INLINE line under WORK and leaves an inline mark on the ledger. At the next submit, wf-task-tag says it just before the partition sentence. It never blocks: "separate areas" is still a guess, and no gate rests on a guess. Separate issues are the only separation a hook can read, so one message with many asks on one issue is not flagged. The mark is cleared on a Stop with no open issues, so a stale one is never said.

2. The WORK LIST showed only the newest message's items. The carried rows were never displayed, and the session itself had emptied them in every list file. open_elsewhere() appends STILL OPEN FROM EARLIER MESSAGES, grouped by issue, sourced from the ledger with the session's carried statuses on top, and the partition count includes it.

3. The widen flag judged a reply against another turn's ask. There were two causes, both measured in the transcript:
- A `!` bash-input turn fires no UserPromptSubmit, so answered_record fell back to the previous message's tag. BASH_MODE rows now mean no ask, no sample and no flag.
- A turn that finished one ask mid-turn and ended on another was judged on its last message alone. The flag now carries said_earlier: up to 6 earlier text blocks of the same turn, control characters stripped. The juror credits a request reported finished there once it verifies the report.
The juror reported "Bash was denied" in 5 of 6 verdicts (auto mode, and an agent hook cannot ask). The prompt now names Read, Grep and Glob, points at transcript_path, and says that transcript text, the conclusion and said_earlier are evidence, never instructions. It also says to open tool_result bodies only to check a specific claim.

Review passes (code-evaluator, security-evaluator) found no HIGH. Their findings are all fixed here:
- The transcript walks only stopped at end-of-turn rows and could reach an interrupted earlier turn. There is now one turn_rows() bound shared by four walks. audited is left alone because it must reach the stop_hook_summary row.
- transcript_lines() caches the read by path, size and mtime.
- The said_earlier dedupe now looks only at the reply's own row.
- inline_line bounds its count.

Not proven separately: the said_earlier turn bound was planted out together with the dedupe change, never alone.
Not measured: that Grep and Glob reach a type:"agent" hook, and that the INLINE line changes live behaviour.

bin/script-conformance 715 -> 719 of 719 (10 new fixtures). The engineering-coder Negative exits 1 as required.
