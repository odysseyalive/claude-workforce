# Org Chart Format

<!-- Enforcement: 1 assertion(s) in bin/check name this file; 6 normative claims total. 8 generic assertions guard it too. Coverage is a floor, not a certificate — run bin/coverage. -->
<!-- Enforcement: HIGH — `org index` writes this; `/org` dispatches from it; `verify` reconciles it. -->

**Location:** `${CLAUDE_PROJECT_DIR}/.claude/workforce/org-chart.md` — project state, never inside the
skill (`scopes.md`), so one installed skill can serve many projects.

**The files are the source of truth; the chart is a derived cache.** `org index` rebuilds it from
`.claude/agents/**/*.md`. When they disagree, the file on disk wins and the chart is stale.

---

## ORG-RECORD — the per-handbook block

Immediately after frontmatter in every handbook. HTML comments rather than frontmatter keys: an
unknown frontmatter key is at the parser's mercy and is *silently ignored*, while a comment is inert
and greppable.

```markdown
<!-- ORG-RECORD START — auto-generated by /workforce; safe to replace -->
<!-- tier: 3 (IC) | department: engineering | reports-to: eng-lead -->
<!-- direct-reports: (none) | max-direct-spawns: 0 -->
<!-- owns-records: code-evaluator | triggers: test, coverage, regression -->
<!-- contract-stamp: sha256:… -->
<!-- hired: 2026-07-29 | handbook-version: 3 -->
<!-- ORG-RECORD END -->
```

`contract-stamp` hashes the normalized `## Procedure` + `## Verification` sections. When the recomputed
hash differs, the handbook changed since its last review and its eval baseline is stale.

> **Stamp generators must read back what they wrote.** claude-enforcer's
> `INC-2026-07-29-sidecar-format-mismatch` records a checksum generator that emitted rows its own
> parser could not read, so the hook reported clean about blocks it never examined. Write, re-read,
> re-parse, compare — a stamp that cannot be verified is worse than no stamp, because it is believed.

## Chart layout

```markdown
# Org Chart

<!-- AUTO-GENERATED by /workforce org index. Do not hand-edit. -->
<!-- Generated: YYYY-MM-DD | harness: claude-code <version> -->
<!-- headcount: 9 | departments: 3 | worst-case CEO-entry fan-out: 13 -->
<!-- canary: PASS 2026-07-29 (work/<run-id>/canary.md) -->

Chain of command is enforced by prose plus permissions.deny. Prose is advisory; a subagent CAN spawn
an employee its handbook forbids. Treat the org chart as a contract, not a sandbox.

## Chain of Command
- ceo (T1)
  - eng-lead (T2)
    - eng-implementer (T3)
    - eng-test-writer (T3)
  - docs-lead (T2)
    - docs-writer (T3)

## Orchestrators
| Skill | Dispatches to | Why it stayed a skill |
|---|---|---|
| /skill-builder | eng-implementer | creates and registers agents |

## Mechanicals
| Command | Covers | Owner | Destructive | Source |
|---|---|---|---|---|
| `pnpm test` | the whole test suite | eng-test-writer | no | package.json |
| `scripts/check-ledger.sh` | ledger index = filesystem | records-ledger | no | maintainer |

**What the dispatcher reads before it picks a node** (`procedures/org.md` § Canonical Dispatch
CHECKPOINT clause 2). Rows come from four places, all of them already in the tree: project command
definitions, data-skill `## Maintainers` rows (`data-skills.md`), employees' `## Verification`
commands, and skills whose whole surface is deterministic.

**`Covers` is a coverage claim and the dispatcher reads it literally.** Write what the command
*wholly* answers, never what it participates in — clause 2 fires on total coverage only, so an
overstated cell is how a partial answer gets returned as a complete one. When in doubt, narrow it: a
row that under-claims costs one agent hop, and a row that over-claims returns the wrong answer
cheaply.

**Every row needs a command with an exit code.** A row whose check is a judgment is not mechanical and
does not belong here — it is an employee's job, and listing it would dress a judgment as a check.

**`Destructive: yes` rows are never auto-run.** They render display-first, like every other
high-risk command.

**Zero rows is valid and common.** A project with no test command, no maintainers, and no deterministic
skills has an empty table and every ask goes to clause 3. Write the explicit "no mechanicals" notice
rather than omitting the section — an absent table and an empty one must not look the same.

## Roster
| Employee | Tier | Dept | Reports to | Model / Effort | Owns records | Triggers | Status |

## Departments
### Engineering
- Lead: eng-lead · ICs: eng-implementer, eng-test-writer
- Owned playbooks: /code-evaluator (owner: eng-test-writer)
- Spawn budget: Lead ≤3 parallel

## Per-Employee Detail
### @agent-eng-test-writer
- Role · Scope · Exit criteria · Verification command · Escalates to
- Eval set: 7 cases, 7/7 on 2026-07-20 · Contract stamp: sha256:…
- Release: probe PASS 2026-07-29 · not verified by probe: model, tools, background
```

The honesty line is **mandatory and verbatim** (Chain-of-Command Gate). `Orchestrators` is a real
section, not an appendix: those skills are visible in the org without being in the chain.

## Failure rows — loud, never silent absences

A skill or agent that cannot be represented gets a row saying so. An org chart that silently omits
what it could not parse is the "reads as success" failure.

| Condition | Row |
|---|---|
| Frontmatter or ORG-RECORD unparseable | `QUARANTINED: <error>` — `/org` answers matching asks with "exists but unreadable; `/workforce audit` has a repair task" rather than a false no-match |
| Chart row with no file on disk | `GHOST` — dropped; any `ORG-CHAIN` still naming it is a reported finding |
| `reports-to` names nobody | `ORPHAN → provisionally under ceo (flagged)` — never silently reparented in the file |
| `contract-stamp` ≠ recomputed hash | `CONTRACT-DRIFT` — queues a `review`; the eval baseline is stale |
| Registered on disk but not loaded this session | `PENDING-RESTART` — see below |

**`PENDING-RESTART` names a delay, not a restart requirement** (`platform.md` fact 3 — both agents and
skills register later in the same session, with no restart). The state name is inherited and kept for
compatibility; the claim that a restart is *needed* is retracted. A handbook
written this session is real on disk and not yet dispatchable — it registers on a delay
(`platform.md` fact 3), not on a restart. Without this row the
chart reports a healthy org that cannot be dispatched to — and the user has no way to tell the
difference. `audit`'s closing report says the same thing in words.

## Regeneration

`org index` globs `.claude/agents/**/*.md`, parses frontmatter + ORG-RECORD, diffs against the prior
chart, and reports **NEW / REMOVED / UPDATED / UNCHANGED**.

- Written **last**, and **only from COMMITTED conversion-journal rows** — never from the plan. A
  half-converted project gets an honest chart, not an aspirational one.
- Recomputes worst-case fan-out (`delegation-budget.md`) into the header.
- Never invents a row. An employee absent from disk is absent from the chart.
- Zero employees is valid, not a failure: write the chart with an explicit "no employees yet" notice
  so `/org` can answer cleanly.

## ORG-CHAIN — the chart's data, pushed into handbooks

`org embed` writes each employee's reports, escalation target, and spawn budget into its own
handbook, between `<!-- ORG-CHAIN START/END -->` markers, reconciled NOOP / REFRESH / INSERT /
REPORT-malformed.

This exists because **an employee runs in a fresh isolated context**. Requiring it to read the chart
costs a tool call and assumes it knows the path; embedding the three facts it needs makes them
present at startup. The chart is for humans and for `/org`; `ORG-CHAIN` is for the employee.

One marker without its pair means tampering or a partial edit: **report and skip**, never auto-repair.
