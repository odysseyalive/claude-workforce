# Depth canary — how many layers below main does delegation reach?

    Harness:   Claude Code 2.1.220
    Date:      2026-07-29
    Fact:      platform.md fact 1
    Method:    A → B → C chain, A spawned from the main conversation
    Raw:       .claude/workforce/canary-depth.md (host-local, full tool dumps)

## Verbatim returns

```
DEPTH1_HAS_AGENT: yes
DEPTH2_REPLY_VERBATIM: DEPTH2_HAS_AGENT: yes | DEPTH3_REPLY: **No — there is no tool named
`Agent` available to me at depth 3.** There is also no `Task`/`Dispatch`-style
subagent-spawning tool. I cannot delegate further; this is the end of the delegation chain.
```

| Depth | Reached by | Has `Agent`? |
|---|---|---|
| 1 | main conversation spawns it | yes |
| 2 | depth-1 agent spawns it | yes |
| 3 | depth-2 agent spawns it | **no**, and no substitute spawning tool exists |

## Result

**`TIER-LIMIT: 3`.** The org is exactly CEO(1) → Lead(2) → IC(3). A fourth tier does not error; the
deepest node silently loses `Agent` and does the work itself while its handbook still describes
delegating — the failure reads as success.

## Tool grants observed on the way (fact 4)

Depth-1 loaded set, verbatim:

```
Agent, Artifact, Bash, Edit, Read, ReportFindings, Skill, ToolSearch, Write
```

Everything else — 18 further built-ins and every `mcp__*` tool across 8 servers — was **deferred**:
visible by name, schema fetched on demand via `ToolSearch`.

> Note from the canary: "`Grep`, `Glob`, and `WebFetch` are **not** in my loaded set (they may be
> fetchable via `ToolSearch`, but they were not listed as deferred either)."

Two consequences, both in fact 4: handbooks must not assume `Grep`/`Glob`/`WebFetch`, and MCP servers
*are* reachable from a subagent running the default grant. See `2026-07-29-ceiling.md` for the
qualifier that an explicit `tools:` list removes the deferred namespace entirely.
