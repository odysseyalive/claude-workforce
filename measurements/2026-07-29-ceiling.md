# Ceiling probe — does `disallowedTools` withhold a tool that `tools:` requests?

    Harness:   Claude Code 2.1.220
    Date:      2026-07-29
    Fact:      platform.md fact 2c
    Fixture:   .claude/agents/wf-ceiling-probe.md
    Spawned:   from the main conversation (depth 1)

## Why this design

The fixture lists `Agent` in **both** `tools:` and `disallowedTools:`:

```yaml
name: wf-ceiling-probe
tools: Read, Write, Agent
disallowedTools: Agent
```

That is the whole measurement. If `Agent` is absent, the harness **withheld** it — rather than it
never having been requested. Without listing it in `tools:`, absence would be uninformative.

## Verbatim return

```
CEILING_PROBE | HAS_AGENT: no | TOOLS: Read, Write

Both tools are in a single loaded list; I observe no deferred/searchable tool namespace,
no `Agent`/`Task` tool, and no Bash, Edit, Glob, Grep, WebSearch, WebFetch, or MCP
(`playwright-mcp`) tools.
```

## The control

`wf-canary-ic` carries an **identical** `tools:` line and no `disallowedTools:`. The harness's own
agent-type listing reported its tools as `Read, Write, Agent`. Same request, one line of difference,
`Agent` present in one and absent in the other.

| Fixture | `tools:` | `disallowedTools:` | `Agent` granted? |
|---|---|---|---|
| `wf-canary-ic` | `Read, Write, Agent` | — | **yes** |
| `wf-ceiling-probe` | `Read, Write, Agent` | `Agent` | **no** |

## Result

**`disallowedTools` wins over `tools:`.** Fact 2c promoted from DOCUMENTED to MEASURED. The tier
ceiling every IC handbook depends on is real on this host.

## Second, unplanned finding — bearing on fact 4

The probe observed **no deferred tool namespace at all**: no `ToolSearch`, no `mcp__*` names, not
even by name. Fact 4 was measured against agents running the *default* tool set, where ~150 names
were deferred behind `ToolSearch` and every MCP tool was reachable.

**An explicit `tools:` list is exact.** It is not a filter applied over the default grant — it
replaces it, and closes off `ToolSearch` and every MCP server with it. Recorded in fact 4, because
the design consequence is real: an MCP tool a handbook depends on must be named in `tools:`, and
a handbook that assumes it can reach a server via `ToolSearch` fails cold.
